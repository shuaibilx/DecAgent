# Proposal

## Why

DecAgent 的展示重心偏向通用 Python 仓库修复，而现有 `intervention` 判断随工具审批触发，缺少尝试轨迹，不能区分有效探索、重复失败与真正需要人帮助的停滞。将“何时继续、换策略或求助”做成独立、可检查和可评测的执行能力，能够落实本项目展示 Agent 理解能力的目标。

## What Changes

- 将项目定位调整为证据驱动的自主任务介入工作台；Python 修复作为首个可验证场景。
- 增加有界进展轨迹：操作与结果指纹、工作区版本、失败变化和证据引用；重复失败触发检查而不直接等同于求助。
- 在工具结果观察之后增加独立介入检查，使用 Jev 的有限选项判断 `continue / replan / clarify / escalate`，与动作权限判断分开。
- 引入有次数约束的策略调整；主模型基于已有尝试提出替代方法，不能扩大权限、预算或绕开拒绝。
- 需要人帮助时提供具体问题、已尝试方法、证据和所需输入；回答持久化、绑定当前任务证据并通过 LangGraph 恢复。
- 保留已授权安全执行、审批、独立修复验收、记忆与恢复；移除新版运行路径中随工具审批附带的旧介入判断，历史记录仍可读取。
- 增加介入轨迹展示、确定性场景评测和数据导出；无独立人工标签时不声称 Jev 准确率或优于其他 Agent。
- 同步 README、使用指南、架构与可视化、源码职责和验收说明，标明旧报告的历史性质。

## Capabilities

### New Capabilities

- `adaptive-intervention`: 基于进展证据的继续、换策略、需求澄清和升级求助，以及反馈恢复和可复现评测。

### Modified Capabilities

无已归档主规格。本变更依赖 `build-decagent-workbench` 已实现的执行边界、任务持久化、判断接口和工作台；本规格描述新增介入闭环，不重写尚未归档的基础能力。

## Impact

- 规划仍存放在本目录 `openspec/changes/adaptive-intervention/`，实现明确位于同级 `../DecAgent`；原 Waku 源码及运行数据不变。
- 涉及 `decagent/runtime`、`decagent/decisions`、网页工作台与相邻测试；沿用现有 LangGraph、PostgreSQL 事件、审批与预算账本，不新增大型框架或新服务。
- 新判断问题独立版本化，历史问题和审批记录保留兼容；图的兼容策略和恢复验证在设计中明确。
- 付费验证沿用本会话 Jev 总额 1 USD 上限和千问免费额度声明；本轮不自动发布新 GitHub PR 或合并现有 PR。
- 原生 Linux 验收和独立人工标注对照仍是已有待办，不因本次功能验收被标为完成。
