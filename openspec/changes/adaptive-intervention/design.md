# Design

## Context

动机见 proposal.md。目标实现为同级 `../DecAgent`，规划根仍位于 Waku。现有 `DecisionCoordinator.assess` 只在硬规则返回 review 时发送 action_risk 与 intervention；intervention 的 observations 主要是规则原因和代码版本。LangGraph observe 直接回到下一工具或 model，没有独立进展节点。已有 PostgreSQL events、幂等判断记录、clarification 审批、版本摘要和租约可复用。

## Goals / Non-Goals

**Goals:** 让任务在结果边界拥有可观测的进展检查；换策略先于无效重复；求助携带证据，回答可恢复；不改变实际操作的权限约束。

**Non-Goals:** 训练新模型、自动宣称学习提升、自动调整生产阈值、新增多 Agent 集群、扩展到生产运维或代替通用编码工具。独立 Linux 和人类标签对照沿用基础变更待办。

## Decisions

### 1. 以有界轨迹作为介入输入

新增纯进展模块，用规范化动作和有意义输出计算指纹，排除调用 ID、时长等非语义字段。命令返回 status=succeeded 但 exit_code 非零视作失败。保留近期步骤、累计序号和检查标记；重复动作/证据和失败连续性是检查信号，证据变化仅表示观察新颖性，不称作成功或语义进展。所有字段经过现有脱敏，记录与模型输入均受长度限制。

备选“失败 N 次立即询问人”无法区分有效探索；“让主模型自述进展”会把推断当作事实。

### 2. 将进展介入与工具权限分开

新增 `task_intervention` Choice，选项为 continue/replan/clarify/escalate，独立问题版本；旧 intervention 问题只为历史记录与评测兼容保留。新版动作判断只询问 action_risk，不为每个审批重复询问任务介入。

正常、非重复的操作直接继续；出现停滞信号才调用判断器，避免对每个安全读取增加调用延迟。判断器使用同一有界证据，同时保存原始答案与最终路由。未经真实校准的语义建议以 shadow 形式记录，由保守进展规则执行有限调整；已匹配的校准策略可选择介入路由，但不能消除策略调整总上限或越过执行权限。模型缺失、格式无效或结果不明沿用账本和 durable 决策退路。

### 3. 在已有图增加结果边界

observe 记录工具结果并更新轨迹；工具批次结束后进入 progress 节点。continue 回到 model；replan 节点追加由运行时构造的有界策略提示并清空过时队列；clarify/escalate 进入 help 节点。主模型负责提出不同路径，Jev 不生成计划、解释或问题。

默认每个求助周期最多两次策略调整；每次调整给予一小段新观察窗口再检查。人的新反馈开启新的有界周期；全任务时间、调用和费用预算不重置。工具返回未知仍先进入现有 reconciliation，不能当作已失败而盲目重复。

### 4. 求助使用现有确认与恢复契约

运行时从观察记录构造阻塞摘要、最近尝试、证据标识和一个明确的信息请求，复用 `ask_confirmation` 的任务/代码/授权/策略摘要与认证拥有者回复。模型可通过已有 `request_user` 提出业务澄清；有效回复以任务、动作记录及回答摘要去重，同样开启新调整周期。新停滞求助不额外引入通用聊天权限。help 节点前只有可幂等记录，等待使用 LangGraph interrupt；恢复重新读取数据库中的确认记录，反馈只追加一次，不直接授权后续动作。判断与回复读取完成后重新 fencing，失去执行权的 worker 不推进这些节点的 checkpoint。

### 5. 兼容通过加法扩展完成

保留现有节点名称、图版本 1 与数据库 schema 4；新增状态字段有默认值，旧 checkpoint 可在下一 observe 后建立轨迹。现有审批节点、旧 decision apply 和历史 problem contract 保留兼容；新 action-only 判断 apply 同时支持旧双问题记录。无需修改或删除已有任务、checkpoint 和证据。新增事件种类不改变既有消费游标。

### 6. 可视化与验证服务于决策主线

任务详情返回有界进展/介入事件，网页展示实际路由、原始建议和求助材料。README/指南/架构图将介入闭环置于主线。旧验收报告保留原证据，并增加历史版本说明。新报告分别呈现纯模块、实际 SQL+checkpoint 恢复、网页与容器验收；人工标签缺失明确保留，不把合成 fixture 当作人类评测。

## Risks / Trade-offs

- 日志变化造成假新颖性 → 规范化非语义字段，只把指纹作为信号，全任务预算始终有效。
- Jev 建议与规则不同 → 展示两者，校准后才能自动采用语义路由；不预设模型优于规则。
- 重启导致重复提示或重复调用 → 幂等事件键、输入摘要与 checkpoint；恢复专门用实际 PostgreSQL 测试。
- 新字段影响旧任务 → 保留节点和版本、默认状态、老审批回归；升级先验证，现有数据不清空。

## Migration Plan

先完成模块和回归，再核实本机 worker 无活动任务，重建 API/worker 镜像并在同一 Compose 数据上升级；新版本继续读取旧记录。回滚使用此前镜像，新增事件仍保留。发布清单在源码变化后显示旧证明过期，不能继续沿用旧报告当作新版已验证。完成本地验收后生成新版报告；独立 Linux 与真实标注比较继续等待其条件。
