# 发布验收报告

> 历史范围：本报告保存基础工作台版本的验收。人工介入改造已改变源码，新版需独立验收；旧 release manifest 的源码哈希不能证明当前版本通过。独立 Linux 与真实人工标注对照待办继续保留。

生成基础版本报告时，本机实施已具备可用工作台，首发门槛为 **incomplete**，缺少独立 Linux 主机、人工标注与真实三策略质量对照。按用户明确意见，Linux 保留待办；不使用 Docker Desktop 的 Linux 容器结果替代它。人工介入改造后，原有源码绑定的通过记录也已过期，下面的结果只保留历史依据。

本次最终检查：Ruff 通过；Python 3.11 Linux 容器离线 385 项通过；Windows PostgreSQL 集成 99 项通过；真实 Docker 执行/修复 20 项通过；固定检查器在 Linux 容器另外定向 7 项通过。Windows 离线 384 项通过、1 项 POSIX 跳过，该断言已由 Linux 容器覆盖。这些是不同运行范围，不能直接相加为唯一测试数量。

API/worker/PostgreSQL/broker/proxy 的本机实例正常；空配置的新 Compose 实例也通过拥有者初始化、认证 CLI、只读根文件系统与 socket 分配检查。原 Waku 基线的 102 个文件哈希均未变化。

千问与 Jev 的默认 API 诊断、真实 PR #2 修复、PR #3 响应未知恢复、版本 4 备份和不可兼容升级阻止/镜像回滚均有本地回执。Jev 目前累计已知费用 **$0.000213402**；千问依据用户确认的免费额度记增量 0，不伪造供应商账单。

证据清单位于 `.decagent/release/manifest.json`，逐项审计摘要和日志位于 `.decagent/release/evidence/`。源码摘要绑定产品与运行配置，文档不影响它。历史真实修复/故障演练保留原 run ID，本次通过当前回归及 GitHub GET 重新核对关联草稿和未变基准；不是又执行了一轮付费修复。清单是本地验收生产者的版本绑定声明，不是第三方认证。
