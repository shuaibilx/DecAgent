## 改变了什么

| 能力 | 当前实现与边界 |
| --- | --- |
| 有界尝试证据 | 最近 20 次观察，排除执行标识、容器名、请求哈希及耗时噪声；内容变化保留。指纹新颖性不等于任务成功 |
| 独立介入判断 | `task_intervention` 的 continue / replan / clarify / escalate，与工具授权分开 |
| 有界调整 | 默认每轮最多两次调整提示；已有尝试写入提示，要求新的可测试假设；提示不证明模型已改变策略 |
| 具体求助 | 根据实际信号整理最近八次尝试、目标、结果摘要及定位/预期行为请求 |
| 反馈恢复 | 稳定问题、版本绑定、PostgreSQL checkpoint；运行时求助及 `request_user` 新回复均开始新局部周期，总预算不重置 |
| 可靠性 | 判断/回复返回后重新检查租约；重复恢复不重调 Jev、不重做已确认动作、不重复追加回答 |
| 工作台 | 最多 50 条进展/介入事件；显示原建议、实际路由、调整、求助和回答；确认材料可展开 |
| 评测入口 | `intervention-report` 导出合成场景或认证任务轨迹；标签保持空值，准确率和收益保持未测得 |

新版动作判断去掉附带的旧 `intervention` 请求，只判断 `action_risk`。旧双问题记录及旧 ID 保留兼容；持久新 ID 增加任务和版本上下文，修复不同任务相同输入的记录碰撞。应用 schema 版本 4、graph 版本 1 以及原节点名称保留。

Jev 新问题没有真实人工校准，当前模型建议只供观察，程序按有界规则路由。更改校准必须匹配实际模型、问题、策略及数据版本。未知工具效果先核实，不能按失败直接重试。动作、代码信任、记忆和发布的原有治理仍各自生效。
