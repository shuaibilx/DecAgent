# 业务 API 与规划协议

当前完成证据与拒绝响应用量实现的回归、真实功能探测及源码指纹见[现版本验证](../261013/0158_现版本修复与功能验证.md)；修复前完整性能对照保持独立。

## 接入与身份

| 项目 | 契约 |
| --- | --- |
| API 前缀 | `/api/v1` |
| 身份 | 单个拥有者；业务目录中的人员不是登录账户 |
| 命令行身份 | 本地保护的 `owner.token`，通过 Bearer 请求 |
| 浏览器登录 | `POST /auth/session`，JSON `{token}`，要求配置的精确 Origin |
| 浏览器写请求 | HttpOnly session cookie、精确 Origin、`X-CSRF-Token`、`Idempotency-Key` |
| 幂等 | 写请求使用稳定键；同键同请求返回原结果，同键不同内容冲突 |
| 插件安装 | 本地可信管理 CLI；网页请求不能提供脚本路径、环境变量或新权限 |
| 默认网页 | `/` 业务工作台；`/repair` 历史仓库修复入口 |

## 端点

| 方法与路径 | 请求或结果 |
| --- | --- |
| `GET /plugins` | 作用域、插件名称/版本/摘要、启用状态、级别、命令及效果/确认规则 |
| `POST /business/tasks` | `scope_id`、`instruction`、`strategy`、可选 `budget`；返回 201 |
| `GET /tasks` | 新旧任务；`kind` 区分 `business` 与 `repository_repair` |
| `GET /tasks/{id}` | 任务、判断、动作、审批、等待原因及业务完成记录 |
| `GET /tasks/{id}/events` | SSE；事件按持久化 `seq` 排序，可用 `after` 和 Last-Event-ID 续传 |
| `GET /tasks/{id}/events?follow=false` | 一次读取持久化事件，便于离线核对 |
| `POST /tasks/{id}/cancel` | 撤销租约并取消；后台不能继续提交旧租约的结果 |
| `POST /tasks/{id}/resume` | 恢复等待中的任务；预算暂停必须提交完整的新预算 |
| `POST /approvals/{id}/reply` | 摘要绑定的拥有者回复；业务回复后自动排队恢复 |
| `POST /tasks/{id}/responses` | 仅澄清回复：`question_id`、`expected_digest`、`content`；绑定当前 clarification 问题 |

### 业务提交

```json
{
  "scope_id": "00000000-0000-4000-8000-000000000001",
  "instruction": "请创建一个 Network 工单，VPN 无法连接，工作已中断",
  "strategy": "hybrid",
  "budget": {
    "max_calls": 30,
    "max_tokens": 100000,
    "max_active_seconds": 1800,
    "max_cost": "0.10"
  }
}
```

| 字段 | 约束 |
| --- | --- |
| `scope_id` | 已登记且启用的真实 UUID；示例 UUID 是占位符 |
| `instruction` | 非空，最多 65536 字符 |
| `strategy` | `rule`、`main`、`hybrid`；默认 hybrid |
| 授权来源/插件摘要 | 服务端冻结；客户端伪造字段被拒绝 |
| 业务任务仓库字段 | 不要求 GitHub 项目、base SHA 或修复执行器 |

### 回复

| `decision` | 必需附加信息 | 后续行为 |
| --- | --- | --- |
| `approve` | `expected_digest` | 查询当前资源；同一提案才授权，过期则重新判断 |
| `reject` | `expected_digest` | 任务停止，不执行业务变更 |
| `edit` | `expected_digest`、完整 `edited_params` | 校验同源 Schema，生成新提案并重新确认 |
| `confirm`（澄清） | `expected_digest`、具体 `confirmation` | 将拥有者补充作为事实重新准备上下文 |

同一审批的相同语义回复可复用；不同回复返回冲突。确认不能同时暗中修改参数。
旧摘要、另一问题或另一动作的回复不能作为当前操作授权。

## 主模型协议

| 项目 | 规则 |
| --- | --- |
| 业务工具 | 插件输入 Schema 生成 `plugin_<command>_<digest>`；不开放任意 shell |
| Skill | 仅从可信安装包读取有大小限制的 UTF-8 `SKILL.md` |
| 工具结果 | 实际 JSON 结果、action ID 和核实信息作为对应 tool message |
| `decagent_ask_user` | 必需具体问题；创建持久化澄清等待 |
| `decagent_finish` | 必需摘要及非空声明 ID 集合 C；W ⊆ C ⊆ O，全部写入必须引用，辅助读取可省略；最终用完整 O 核实持久回执与目标 |
| 无效规划 | 保存固定 rejection_reason、严格 usage 和安全 resolved_model；proposals=[]，最多两次无效响应后询问拥有者 |
| 精确 JSON 指令 | 绑定原命令及用户参数；模型不能换参数获得自动授权，完成检查也核对参数 |
| 用户编辑 | 拥有者回复记录授权修改；更新目标参数，生成新提案并重新确认 |
| 澄清后规划 | 保留已核实操作的完整结果和 action ID；不把已完成写入当作新任务 |
| 延迟初始化 | 只有路线需要规划时才建立主模型；业务启动不建立 GitHub/broker 客户端 |
| 基础插件 | 主模型使用注册工具规划，不要求增强工作流 |
| 增强插件 | 可按冻结问题和真实候选走规则/Jev；复杂参数和复合操作仍可进入主模型 |

## 预算与完成

| 项目 | 定义 |
| --- | --- |
| 调用计数 | 每个实际请求先持久化 reservation；失败/未知请求也占额度 |
| token/费用 | 完整但提案无效的响应仍按合法用量结算；未知价格仅 tokens 已知；缺失或非法用量及传输中断保留预留 |
| 派发前拒绝 | 仅可信本地预检或派发守卫可结算 0 token/0 费用；通用或供应商异常不构成证明 |
| 新业务动作 | 同一任务锁内确认调用数、token、费用、机器时间仍有余量，才转 running |
| 已发出的未知写入 | 调用/token/费用耗尽仍可只查询回执；机器时间耗尽须先调整预算 |
| 已成功动作 | 返回原持久化结果，不重复执行 |
| 人工等待 | 不计机器 active_seconds |
| 创建任务成功 | 创建回执核实即可；工单可仍为 open |
| 创建并分派成功 | 同一工单的两个操作均核实；工单可仍为 assigned |
| 模型成功文本 | 单独不能证明完成 |
| 无法证明注册目标 | 完成声明 failed，reason=goal_unproven；程序摘要及全部动作保留，不追加写入 |

## 当前验收范围

业务 API 与生产业务图的 PostgreSQL 联测已覆盖批准、拒绝、编辑、过期确认、澄清及 CSRF。
真实模型固定集评测、浏览器操作验收和独立 Linux 部署状态以对应验收报告为准。
本机受控插件 runner 当前要求 Windows；不能把 Linux 容器中的业务启动视为可用。
