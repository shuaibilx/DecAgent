# 业务插件与工单 JSON CLI 接入指南

插件源码在 `decagent/business/`。内置 `service-tickets` 是独立的 PostgreSQL 工单服务，
仅处理合成人员目录、服务分类和用户记录，不表示连接了真实企业后台或已经修复设备。

## 契约和可信入口

`PluginSpec.from_mapping(manifest)` 校验并冻结 JSON 清单；`digest` 是其规范 JSON 的 SHA-256。
清单的基础字段为 `id`、语义版本 `version`、`level`、`entrypoint` 和非空 `commands`。
`level` 为 `basic` 或 `enhanced`。每条命令必须提供 `input_schema`、`effect`、
`confirmation` 和 `result_schema`。参数中的对象必须声明 `additionalProperties:false`；
对象、数组、枚举、布尔和数值统一使用 JSON Schema Draft 2020-12 校验。禁止外部 schema 引用。

省略 `type` 但包含 `properties`、`patternProperties` 或其他对象约束的节点也必须关闭未知字段；
组合分支、数组元素、`dependentSchemas` 和本地引用目标递归遵守同样要求。新的参数值不能
使用允许任意对象的空 schema 或 `true`；类型通过 allOf/anyOf/oneOf 和引用推导，字符串父
schema 下的 `allOf:[{"minLength":2}]` 等合法同值约束仍可使用。闭合的本地引用或组合、有限
enum/const 也可证明不会接受未知对象字段。所有仍允许数组的参数路径必须为元素提供受约束
schema，包括省略 `type` 或仅用 `not` 排除对象的路径；否则须明确排除数组。
注册时解析 `$ref`、`$dynamicRef`，拒绝外部 URI、缺失指针/anchor 和非 schema 目标；
Draft 2020-12 不支持 `$recursiveRef`，因此直接拒绝该旧关键字，避免被校验器静默忽略。
运行校验使用无网络读取的 Registry；引用解析错误转换成具体 `ValueError`。实现采用
[jsonschema 的 referencing API](https://python-jsonschema.readthedocs.io/en/stable/referencing/)。

模型工具通过 `tool_schemas()` 从这些参数 schema 生成，运行前的 `validate(command,params)`
使用相同 schema。未声明的命令或参数、错误嵌套值及非法 UUID 在启动 CLI 前拒绝。

增强插件还提供包内 `skill` 和含 `version`、`branches`、`questions`、`parameter_sources`、
`completion` 的 `workflow`。查询型增强插件可不提供 `states` 和 `transitions`，也可提供空迁移表。
提供状态机时，状态名称唯一，迁移引用已注册命令及存在的状态。版本为数字或语义版本字符串。
分支有非空条件及合法路由，参数来源引用真实声明的参数，
完成条件为非空命名条件。Choice 只允许已注册命令候选并必须保留 `no_match=true`；Noul 必须
提供非空命题；Score 包含 2–10 个从 0 连续递增的整数等级和不同的非空情境描述。问题 ID 唯一。
基础插件无需提供 workflow。内置完整清单在
`decagent/business/tickets/manifest.json`，技能在同目录 `SKILL.md`。技能文本提供任务上下文，
不增加命令执行授权。基础契约不会声称拥有增强流程的快速路径。

入口采用固定已安装 Python 模块 `{"module":"decagent.business.tickets.cli"}`，或用户显式注册的
固定参数数组 `{"argv":["绝对可执行文件路径","固定参数"]}`。自然语言和业务参数不会成为
可执行入口，也不会进行 shell 拼接。注册意味着信任这段插件代码，不能用本机制执行不可信代码。

`PluginRegistry(database).register(manifest)` 保存版本、内容和摘要，返回业务作用域行；
同一插件 ID 更新时保留作用域 ID。`get(scope_id,expected_digest=...)` 拒绝摘要变化、内容损坏
或已禁用插件。`disable(scope_id)` 使旧任务暂停复核。注册相同内容不会无故递增版本。

## 受控运行

`CliRunner(environment=...).run(spec,command,params,operation_id,cancelled=...)` 使用
`shell=False` 参数数组，通过 stdin 发送一个 JSON 对象，严格解析 stdout 中的一个 JSON 回应。
不会继承模型、GitHub 或 owner 密钥；业务配置仅从调用者显式提供的、清单允许的环境变量注入。
内置服务只允许 `DECAGENT_TICKETS_DATABASE_URL`。运行支持变量仅包括 Windows 系统目录、
临时目录和 Python UTF-8 配置，不传递父进程 PATH 或 PYTHONPATH。

默认限额为 15 秒、stdout 与 stderr 合计 256 KiB、两个进程；请求 JSON 最多 64 KiB。
Windows 中，虚拟环境 Python 包含一个启动器和一个解释器，所以默认进程限额为两个。
子进程以暂停状态启动，在执行代码前加入 Windows Job Object；该 Job 限制活跃进程数，
取消、超时或结束时关闭 Job 并终止整棵进程树。取消在启动前也会检查。
当前 POSIX 入口在启动前返回 `unsupported_platform`，不会以较弱约束执行。
Linux 业务 CLI 必须先部署提供等价进程数限制的受控 adapter；独立 Linux 部署仍待验收。

共享 JSON 解析器在解码前以迭代扫描限制嵌套深度为 64，忽略字符串里的括号，并把解析器
递归异常转换为结构化错误。NaN/Infinity 和 `1e999` 这类溢出为非有限浮点数的值均被拒绝；
相同边界同时保护 CLI 的 stdin 输入与 runner 的 stdout 回执。
重复 JSON 字段、额外 envelope 字段、错误 schema、输出超限或退出状态与
成功回执冲突都会被拒绝。运行错误不会把 stdout/stderr 中的原始内容或配置凭据回传给用户。
超时、取消或无效输出后，写入可能已发生，应先查询业务回执。

## 独立 CLI 启动

先从项目根目录运行应用迁移命令，安装包含 `006_service_tickets.sql` 的 schema。
CLI 不在启动时建表、不加载 `.env`、不调用外部模型或企业 API。
通过可信本地配置设置 `DECAGENT_TICKETS_DATABASE_URL`，勿把 URL 写进模型指令或文档。

PowerShell 中以下请求通过 JSON stdin 调用独立入口。首次合成目录初始化是显式管理员操作；
`seed` 不在模型工具清单中。

```powershell
'{"command":"seed","params":{},"operation_id":"seed-directory-v1"}' |
  .venv/Scripts/python.exe -m decagent.business.tickets.cli
'{"command":"directory","params":{"kind":"people","query":"张伟"},"operation_id":"lookup-people"}' |
  .venv/Scripts/python.exe -m decagent.business.tickets.cli
```

成功输出为 `{"ok":true,"data":...}`，失败为
`{"ok":false,"error":{"code":"revision_conflict","message":"..."}}`。
请求必须严格包含 `command`、`params`、`operation_id`。CLI 不接受任意 SQL、shell 或命令行参数。

## 参数和状态

| 命令 | 参数 | 结果与确认策略 |
| --- | --- | --- |
| directory | 可选 kind=people/categories/all、query、team | 返回 people 和 categories 数组；读操作自动 |
| create | title、category_id；可选 description、requester_id、priority | 新工单为 open；明确请求可自动 |
| assign | ticket_id、person_id、expected_revision | open/assigned/in_progress → assigned；首次分派可自动，重新分派须确认 |
| start | ticket_id、expected_revision | assigned → in_progress；明确请求可自动 |
| comment | ticket_id、body、expected_revision | 保留状态，添加历史；明确请求可自动 |
| resolve | ticket_id、resolution、expected_revision | in_progress → resolved；必须有用户解决记录并确认 |
| close | ticket_id、expected_revision | resolved → closed；确认 |
| reopen | ticket_id、expected_revision | resolved/closed → open，清除负责人和解决记录；确认 |
| set_priority | ticket_id、priority、expected_revision | normal/high/urgent；已有工单改优先级须确认 |
| get | ticket_id | 返回 ticket 和按 revision 排序的 history |
| list | 可选 status、person_id、limit(1–100) | 返回 tickets 数组 |
| receipt | operation_id | 返回 receipt 或 null |

人员、分类和工单使用稳定 UUID。英文 Zhang Wei 和中文张伟分别有两个不同团队的候选人；
查询保留全部候选，调用者应澄清选择，不静默按姓名合并。分类和人员 ID 必须来自业务目录。
更新前读取当前工单 revision；过期 `expected_revision` 不会覆盖别人已经提交的修改。

## 回执与恢复

成功写入返回 `data.ticket` 和 `data.receipt`。回执字段为 `operation_id`、`input_hash`、
`command`、`resource_id`、`revision`、`result`。`result` 保存原始写入结果（工单快照），
所以后续修改不会改变早期回执。种子操作回执的资源和 revision 为 null，result 保存目录数量。

`input_hash` 计算为 `sha256(canonical({"command":command,"params":params}).encode("utf-8"))`；
canonical 使用键排序、紧凑分隔符、保留 Unicode，并拒绝非有限数值。同一个 operation ID
携带完全相同输入时返回已保存结果；携带不同输入时返回 `operation_conflict`。

写入、递增 revision、历史和回执在同一 PostgreSQL 事务提交。外键延迟到事务结束，支持备份
恢复的表导入顺序。无效目录引用、非法迁移、版本冲突或事务失败不会留下部分工单或回执。
请求结果丢失时，先以原 operation ID 查询 receipt，再 get 验证资源；不换新 ID 盲目重试。
创建并分派任务在这两项回执核实后即可完成，不要求关闭工单。

## 验证

专用测试使用独立 PostgreSQL 数据库和本地已安装 CLI，不调用任何模型服务。

```powershell
.venv/Scripts/python.exe -m pytest evals/deterministic/test_business_plugins.py `
  evals/deterministic/test_business_runner.py evals/integration/test_business_tickets.py -q
```

运行集成测试前以可信私有配置设置 `DECAGENT_TEST_DATABASE_URL`；测试为每个场景创建独立
随机数据库，不清空现有用户数据库。覆盖契约准入、摘要冻结、禁用、嵌套 schema、未知参数、
环境隔离、注入文本、超时/输出限制、Windows 进程树、取消前检查、完整状态迁移、重名候选、
revision 冲突、事务回滚、幂等键碰撞、丢失响应回执及真实独立 CLI 全生命周期。
