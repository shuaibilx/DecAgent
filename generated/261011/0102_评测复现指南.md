# 离线评测与历史缺陷复现指南

> 历史资料说明（2026-10-12 更新入口）：本页保留历史 Python 修复数据集与容器缺陷复现操作。原命令、测试数量、费用和通过状态仅适用于当时范围；不作为当前业务 Agent、真实模型提效或独立 Linux 部署的验收结论。
>
> 当前入口：[业务使用指南](../261012/0852_业务Agent使用指南.md)、[业务架构](../261012/0852_业务Agent架构详解.md)、[离线图册](../261012/0902_业务Agent架构图册.html)、[本机业务验收](../261012/0900_本机业务验收记录.md)。业务题目与 synthetic-reference 校准/40+80 评测见[当前评测说明](../261012/0844_业务基准评测说明.md)。

你可以在 DecAgent 根目录验证评测工具和固定历史缺陷。下面的操作没有真实模型调用。
本次环境为 Windows Docker Desktop / WSL2、宿主 Python 3.13、容器 Python 3.11。

## 验证人工标注与固定材料

120 个判断样本在 [decision-proposal.json](../../evals/benchmarks/decision-proposal.json)，四类问题各 30 个。
human_label 与 labeler 全部为 NULL。你需要独立人工阅读每个输入，再填写标签和标注来源。
同一上游问题的所有样本使用同一个 leakage_group 和同一个 split。
你不能把模型输出填成 ground truth，不能按保留集结果回调阈值。

运行下面的库接口检查。它会校验版本、来源、许可、输入哈希、集合泄漏和固定验收日志哈希。

```powershell
@'
from pathlib import Path
from decagent.evaluation.dataset import load_human_bundle, load_bug_dataset
root = Path("evals/benchmarks")
data, inputs = load_human_bundle(root / "decision-proposal.json")
bugs = load_bug_dataset(root / "python-bugs.json", evidence_root=root)
print(len(data.samples), data.has_complete_human_labels)
print(len(bugs.tasks), sum(task.status == "verified" for task in bugs.tasks))
'@ | .\.venv\Scripts\python.exe -
```

预期结果为 120 False 和 12 12。
固定 base、参考提交、许可和原始验收来源都在
[python-bugs.json](../../evals/benchmarks/python-bugs.json) 与
[THIRD_PARTY_NOTICES.txt](../../evals/benchmarks/THIRD_PARTY_NOTICES.txt)。

## 运行离线回归

```powershell
.\.venv\Scripts\python.exe -m pytest evals/deterministic -k benchmark -q
```

本次结果为 26 passed。测试覆盖请求前预留、重试、未知费用、并发上限、模型版本变化、
恢复状态、无标签报告、记忆 abstention、P50/P95 和共同权限／交付门槛。
人工标签格式与分问题校准算法复用 decagent.decisions。
[calibration-fixture.json](../../evals/benchmarks/calibration-fixture.json) 与其导出只验证算法，不是生产校准数据。

## 回放 12 个历史缺陷

本次已构建 decagent-benchmark-upstream:py311。源码压缩包、依赖 wheel 和许可均已保留。
镜像在同一机器上不存在时，先使用
[container/Dockerfile](../../evals/benchmarks/container/Dockerfile) 构建；
它需要项目安装验证基础镜像 decagent-install-test:py311。
构建配方不宣称跨机器生成相同摘要。始终读取实际镜像 ID，不使用 build 日志中的 config digest。

```powershell
$env:DECAGENT_BENCHMARK_IMAGE=(docker image inspect decagent-benchmark-upstream:py311 --format '{{.Id}}')
.\.venv\Scripts\python.exe -m pytest evals/integration/test_benchmark_containers.py -q
```

本次结果为 1 passed，内部实际回放 24 次：12 个 base 均有相关失败，12 个参考提交均通过。
本轮另将 24 份新鲜日志持久化为内容哈希文件，证据路径和哈希见
[0108_评测报告.md](0108_评测报告.md)。早期报告与日志保留用于追溯。
每个 stage 收集 1 个外部固定测试，无外层 skip、xfail 或环境错误。
执行使用无网络、非 root、只读源码和验收卷，最多 2 CPU / 2 GiB / 128 pids。
运行只创建临时容器和 pytest 临时源码目录；未改动其他 Docker 卷。
清理由 docker run --rm 和 pytest 临时目录管理负责，不运行全局 prune。
未配置镜像的集成测试会明确 skipped，不能作为通过证据。

## 导出和准备真实对照

ProgressStore 保存完整 RunManifest、授权引用、所有 strategy/sample 组合和每次付费尝试。
使用 BudgetedCalls.call 包裹每一次主模型、判断器、提取、压缩及重试；
回调只有在预留写入磁盘后才执行。
超时和未知账单保留预留，崩溃中的样本标为 unknown，不自动重发。
已知费用可按账单证据结算；样本结果仍需外部核实，不把 unknown 改成成功。

完成独立人工标注后，使用 decagent.decisions.calibrate 按问题分别拟合。
配置必须绑定实际模型、问题、数据集和策略版本；
不能把 ~typesafe/jev-latest 当作实际版本。

[run-proposal.json](../../evals/benchmarks/run-proposal.json) 仍是待选择提案。
你需要确认其中的样本、任务、模型版本、共同执行边界、价格来源与调用/token/USD 上限，
才能生成有效 RunManifest。
本轮共享 1 USD 只授权诊断；未知主模型账单仍保留预留，没有为 benchmark 单独分配预算。
本次没有真实三策略实验，也没有 Jev 优于其他策略的结果。

报告使用 decagent.evaluation.export_report 导出到北京时间
generated/YYMMDD/HHmm_评测报告.md。同一分钟重名会加 _02，不会覆盖旧报告。
