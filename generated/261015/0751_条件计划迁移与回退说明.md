# 条件计划迁移与回退说明

适用实现目录：DecAgent。对应 change：jev-conditional-workflows。原始记录：2026-10-15 07:51；更新：2026-10-16，北京时间。

源码已增加迁移 012–017：计划、分类预算、阈值策略、语义待办、业务记忆和流程注册。独立测试已覆盖条件解释器和真实 MCP 崩溃恢复。新旧版本分派已经实现，见[版本分派参考](1941_业务图版本分派与回退参考.md)；用户业务库尚未迁移。

当前默认入口仍为 business-2。`DECAGENT_CONDITIONAL_WORKFLOWS_ENABLED=true` 可选择新建 business-3；兼容 worker 恢复已有任务不受此开关限制。完整评测和本机发布尚未完成，因此当前服务配置保持关闭。

## 已留存的基线

[基线清单](0747_business2基线/manifest.json)记录原源码每个文件的 SHA256、业务图版本 business-2、数据库版本 11、MCP 版本和模型配置名称，不包含密钥。源代码与相关测试保存在同目录 business-2-source.zip。

固定测试从冻结包解出后执行，使用独立数据库、真实 loopback MCP HTTP，未请求模型。[测试记录](0747_business2基线/fixed-mcp-task-test.log)结果为 1 passed。该结果证明留存入口可执行固定任务，不证明模型判断正确率或性能改善。

[新旧版本夹具](../../evals/integration/conditional_support.py)建立业务图 business-2 与 business-3 的独立测试任务，并保存一个未提交且运输结果视为未知的准备操作。[保留检查](../../evals/integration/test_business_conditional_versions.py)确认迁移不会改图版本、员工或操作 ID，也不会产生业务写入回执。它目前只验证持久数据保留，不代表新图执行已经完成。

## 实施迁移顺序

当前 [BusinessWorker.claim](../../decagent/business/worker.py) 按应用 schema 检查兼容性，再领取业务队列；运行时分别选择 business-2 和 business-3 图及服务。未知版本仅隔离对应任务。恢复检查 checkpoint 标签与该任务的版本一致，不要求整个队列同版本。旧的单版本限制已移除，不通过修改持久版本标签来绕过检查。

1. 先检查基线 manifest 和 archive SHA256，确认运行入口、源码、schema 与测试证据均可追溯。
2. 关闭新图任务创建入口时添加下一号迁移，保持旧迁移文件及其校验和。先在独立测试数据库验证旧数据迁移和重复迁移。
3. 部署兼容两种图版本的 worker。已有 business-2 checkpoint 由其兼容入口恢复；新 business-3 由条件计划解释器恢复。未知版本明确隔离，不能令已支持版本全部停止。
4. 验证租约过期接管、写入确认、原员工重新认证、提交响应丢失、人工等待和预算等待。每种恢复都保持原任务、节点和操作身份。
5. 通过功能检查后，再启用新任务入口；有效自动阈值和复用模板按各自验证报告发布。
6. 更新使用指南中的实际启动配置与本说明，再对本机工作台验证。独立 Linux 部署仍属于后续待办。

当前已有本机管理入口如下；实际迁移前必须先完成上述独立数据库验证。不要把测试数据库 URL 设置为业务库 URL。

~~~powershell
python -m ops.local.start migrate
python -m ops.local.start worker --kind business
~~~

命令从 DecAgent 根执行。ops.local.start 使用现有本机 PostgreSQL 端口及秘密文件配置；一般启动指南中的密钥仍只保存在本地。

## 回退方式

回退新任务创建入口不等于降级已有 checkpoint。已有 business-3 任务需继续由兼容 worker 恢复，或者明确暂停并记录原因。保留新增持久表与原任务证据，不把 business-3 改标为 business-2，也不重新播放已提交写入。

原 business-2 任务继续使用保留的兼容入口。冻结包用于隔离基线和排查；旧包绑定旧 schema 时不能直接作为新增 schema 的生产回退包，兼容运行器必须经过迁移回归。

## 核实结果未知的操作

准备、确认、提交和核实是不同阶段。只要提交结果未知，就继续查询原 operation_id；返回实际已提交回执才记成功。没有得到可验证“未提交且无在途请求”的结果，不能换 ID 重试。

员工语义选择、记忆更新或计划重规划都不能让未知提交消失。计划修订需把这些节点列为冻结区。已经成功的副作用只有显式授权的补偿业务才能改变，不能通过编辑历史记录撤销。

~~~mermaid
stateDiagram-v2
    [*] --> Planned
    Planned --> Prepared
    Prepared --> AwaitingConfirmation: 需要具体写入确认
    AwaitingConfirmation --> Committing: 原员工有效确认
    Prepared --> Committing: 契约允许直接提交
    Committing --> Verified: 已核实回执
    Committing --> Unknown: 超时/进程退出
    Unknown --> Verified: 原操作已提交
    Unknown --> Unknown: 仍未能核实
    Unknown --> Committing: 协议证明可用原身份重试
    Verified --> [*]
~~~

## 检查口径

隔离集成测试通过不等于生产迁移完成。真实模型阈值、任务质量和性能另有冻结评测。当前独立测试数据库通过以下文件验证保留行为：

~~~powershell
python -m pytest evals/integration/test_business_conditional_versions.py -q
~~~

集成测试需要专用 DECAGENT_TEST_DATABASE_URL，并由夹具创建独立 case 数据库。没有该配置导致 skip 时记录为未执行，不能记作通过。
