# 任务工作记忆与有界业务上下文

原记录：2026-10-15 15:00；更新：2026-10-16（北京时间）。对应 OpenSpec jev-conditional-workflows 6.1–6.2。

实现位于 [business/context.py](../../decagent/business/context.py)。本模块仅提供同一业务任务的工作状态投影、上下文构建与有审计来源的语义更正；不创建跨任务数据库记忆，也不修改旧 repair/project memory。通用规划上下文不自动检索跨任务记忆；已发布工作流只能通过稳定记忆槽显式读取当前员工的有效记录，解析由运行时代码完成，不调用 Jev。Jev 只可在固定写入模板下评估记忆提议。

## 数据口径

事实来自当前 PlanRepository 的租约保护事务，包括有效计划、全部节点 generation、Jev 原始批次事件、已消费节点结果、原员工动作日志、服务端写入确认、任务审批与持久用量。不会全量拼接普通日志，也不会重新执行工具以重建状态。

只有最高 generation 且 node_digest 匹配当前定义的节点标为 active。已认证 action edit 产生 business.node_superseded 后，旧 waiting 代保留状态和事件引用并标记 superseded；新代尚未创建时，不把旧等待继续视为活动待办。instruction 使用同一认证更正规则折叠 literal 目标，original_instruction 保留原请求。活动的 succeeded/waiting/unknown/failed/skipped 节点及已准备、已分派节点均属于冻结前缀。

三种值应分开读取：

- `decisions[node_id].raw_answer`：原 Jev 回答；问题和策略引用保留已发布版本，`actual_model` 保留实际解析版本。
- `decisions[node_id].accepted`：运行时是否已消费该回答。批次响应成功不等于每个旁支答案均已接受；批次和消费节点都须匹配当前权限 epoch。
- `decisions[node_id].effective`：当前语义选择。没有人工更正时仍标为 `inferred`；有效人工更正标为 `user_confirmed`。这两个来源都不代表业务动作已执行。

节点完成只表示节点记录已保存。实际业务副作用另外查看 `actions`：只有成功日志及有效的 `server_verified/input_bound` 回执同时成立，并匹配原员工与契约，才标记 `verified=true`。该标记证明历史执行；当前工单状态仍须由新授权读取确认。未知动作保留原 `request_id`、`operation_id`、参数和事实引用，不改称成功。

员工、scope、scope_revision、account_revision、角色和团队来自当前数据库记录。历史观察的 epoch 已过期时，保留其引用和 `requires_refresh=true`，不再把旧业务值送入上下文。投影或人工语义选择不能授予写入权限。

实际路径另外区分 `active_nodes`、`ready_nodes`、`pending_nodes`、`blocked_nodes`、`inactive_nodes` 和 `stop_nodes`。定义仍属于当前 generation 不代表该分支实际走过。未来可能使用的字段保持必要性；已经确定不走的分支不会要求加载其记忆或把其 Jev 回答当作当前选择。

普通澄清与语义待办均重验节点、员工和权限版本。重规划的 `required_evidence` 也必须匹配已存节点输出摘要，不能通过直接附加 raw output 绕过 epoch 过滤。经认证参数更正后，旧 generation 可作为历史触发引用，但其正文不能被当作新事实。

## 重建与持久索引

~~~python
from decagent.business.context import TaskWorkingMemory

memory = TaskWorkingMemory(repository)
snapshot = memory.rebuild()
facts = snapshot.to_mapping()
source_digest = snapshot.digest

# 需要临时只读重建时，不更新索引。
read_only_snapshot = memory.rebuild(persist=False)
~~~

`repository` 必须是当前 business-3 的 PlanRepository，且持有原员工身份和有效 worker 租约。尚未发布计划时也能生成初始上下文，此时 `plan=None`，没有 plan head 可写索引。

只在 `business_plan_heads.context_snapshot["working_memory"]` 保存版本、来源摘要、计划摘要与节点/事件/动作/审批引用，索引上限 65,536 UTF-8 字节。不复制大工具结果、完整事件或回执正文；保留 context_snapshot 的其他组件键。

每次 rebuild 都从事实表读取，缓存缺失、过期或被污染均不能制造已完成操作。事实已提交但索引尚未更新时，下一次 rebuild 能恢复新节点结果和未知状态。索引更新本身不产生新的业务事实事件。

## 有界规划与判断输入

~~~python
from decagent.business.context import ContextBuilder

builder = ContextBuilder(snapshot)
initial = builder.planning()
planner_mapping = initial.to_mapping()

# 局部重规划显式携带原因和当前 parent_revision。
replan = builder.planning(replan_reason="new_observation")

# 只允许计划中已注册的 decide 节点。
judgment = builder.decision("category")

# 需要消息格式时：固定系统约束 + 单独 user JSON 数据。
messages = replan.messages()
assert replan.model_requests == 0
~~~

允许的重规划原因与既有规划器一致：`new_observation`、`uncovered_condition`、`user_goal_changed`、`capability_unavailable`、`contract_changed`。

默认上下文上限为 12,000 token，JSON 数据另有限额 48,000 UTF-8 字节。未知模型 tokenizer 时，使用“每个 UTF-8 字节计一个 token，加固定消息约束和 framing”的保守上界，而不是宣称精确 tokenizer 数量。`token_upper_bound` 是上界，不能冒称真实提供方 usage。

生产规划器使用 `ContextBuilder(snapshot, system_prefix="")`，因为规划器自己提供可信系统 prompt；消息组装不重复添加两段系统约束。完整请求另在 `ConditionalPlanner` 按 65,536 的默认保守输入上限检查，包含系统目录、工具 schema 与消息 framing；12,000 是业务事实部分的预算。目录压缩只提取重复 JSON 片段，可无损展开，不删除参数和判断尺度。

必要部分包括原指令和约束、当前身份边界、有效计划及冻结节点标识、已提交/未知动作、审批、外部 Jev 判断与人工更正、预算和重规划原因。冻结节点的完整定义保留在同一上下文的 plan.nodes。

观察值按计划中的真实 node_output 引用路径提取；不存在的字段显式保留 missing=true，不生成占位 ID。literal 中的普通 JSON 对象不增加依赖。其余完整观察仅在预算允许时追加，按固定来源顺序选择；未选中的正文仍有 digest 和原事实引用可核对。这是确定性筛选，不生成自然语言摘要。

~~~python
from decagent.business.context import ContextBudgetError

try:
    bounded = ContextBuilder(snapshot, max_tokens=12000).planning()
except ContextBudgetError as exc:
    assert exc.code == "mandatory_context_exceeds_budget"
    # 暂停或由调用方缩小重规划范围；不能删掉未知提交或权限边界后继续。
    required_upper_bound = exc.required_tokens
    configured_limit = exc.max_tokens
~~~

`required_tokens/max_tokens/required_bytes/max_bytes` 可用于解释暂停。模块不截断必要字段、不添加摘要模型请求，也不隐藏提供方费用。

## 人工语义更正

在服务器已取得原员工浏览器身份后，可追加任务内更正：

~~~python
decision = snapshot.to_mapping()["decisions"]["category"]
correction = memory.correct_decision(
    "category",
    selected_value,
    identity=authenticated_employee_identity,
    expected_plan_digest=repository.current().digest,
    expected_decision_digest=decision["digest"],
)
updated = memory.rebuild()
~~~

接口重新核对原员工、活跃浏览器会话、account revision、当前 worker 租约、计划摘要和原判断摘要。Noul 选择 bool；Choice 必须选择原合法分布中的键；Score 必须选择原量表中的整数档位。

更正事务只追加 `business.context_correction` 事件。原始 decision_batch、原节点结果、action/receipt 不修改。更新投影失败后仍可根据该事件重建；重复使用旧 expected_decision_digest 会被拒绝。

返回的 `source_ref` 指向新审计事件；有效选择保存在后续工作状态的 effective 中。该接口不批准写入，不代替持久人工待办 API，也不会自行改变运行时节点绑定或执行 MCP。后续动作仍须经过现有参数、身份、权限、新鲜度、独立确认和幂等回执检查。

运行时绑定统一使用 `selected_value`：Choice 为真实候选 ID，Noul 为 bool，Score 为合法档位。人工选择不伪造 `confidence=1` 或 Noul 概率；原始模型分布单独保留。当前可信模板指纹已包括此字段，旧指纹的计划必须重新校验。

~~~mermaid
flowchart TD
  E[当前员工与版本下的工具结果 / 回执 / 原回复] --> F[任务事实日志]
  J[Jev 原始分布] --> I[推断与门控记录]
  H[原员工语义选择 / 更正] --> U[经认证的当前选择]
  F --> W[可重建工作记忆]
  I --> W
  U --> W
  W --> C[确定性筛选与上下文预算]
  C --> P[规划器数据消息]
  C --> D[可信问题的 Jev state]
  F --> S[业务记忆候选来源]
  S --> A[当前权限 / 来源 / TTL / 版本过滤]
  A --> M[Jev 筛选提议]
  M --> K[偏好需本人确认；经验需已发布规则与真实回执]
  K --> L[有限跨任务业务记忆]
  L --> A
~~~

跨任务存储及写入提议筛选分别见[业务记忆存储](2000_员工范围业务记忆存储参考.md)和[业务记忆写入提议可信筛选](../261016/0342_业务记忆可信筛选.md)。计划中只声明稳定槽，不保存员工记录 ID，也不允许任务输入覆盖它：

~~~json
{
  "source": "verified_memory",
  "memory_kind": "confirmed_preference",
  "subject": "response_language",
  "path": ["value"]
}
~~~

执行时运行时以当前认证员工为范围，将槽解析为 `confirmed_preference:response_language`，并在节点分派前重新验证唯一性、当前版本、TTL 和来源。找不到唯一有效值时暂停；通用规划器不接收记忆候选，Jev 也不负责决定是否读取。该图中“推断”“当前选择”“实际执行”保持分开；长期记忆不能缓存当前权限或充当写入授权。执行恢复细节见[条件计划执行与恢复](../261016/0917_条件计划执行与恢复.md)。

## 安全与验证

工具文本、用户文本及模型推断只进入独立 JSON 数据消息。系统约束由模块常量提供。检测到已知凭据、常见 token/密钥模式或不支持的数据结构时抛出 ContextSafetyError，不把敏感值复制进异常文本。

验证文件：

- [确定性上下文测试](../../evals/deterministic/test_business_context_bounds.py)：复制隔离、UTF-8 上界、必要事实超限、字面量不伪造依赖、凭据拒绝、来源摘要校验。
- [数据库集成测试](../../evals/integration/test_business_context.py)：事实先提交后投影恢复、原始/已接受判断分离、人工更正与原审计共存、会话和版本拒绝、scope epoch 过期、冻结/未知操作保留、真实回执、零模型请求。

从 DecAgent 根执行；独立数据库凭据只在测试子进程环境读取，不能打印，也不使用业务数据库：
