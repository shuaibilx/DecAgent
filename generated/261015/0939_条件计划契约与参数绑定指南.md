# 条件计划契约与参数绑定指南

本阶段交付计划数据契约、可信问题目录、编译器、参数绑定、规划器适配层与完成证据检查。当前业务入口仍是旧运行图；这些组件将在持久解释器阶段接入，新循环尚未启用。

## 已实现的组件

| 模块 | 可验证的行为 |
| --- | --- |
| [contracts.py](../../decagent/business/plans/contracts.py) | Plan.from_mapping 创建不可变 JSON 快照；校验版本、节点/条件结构与大小，并派生内容摘要 |
| [plan-schema.json](../../decagent/business/plans/plan-schema.json) | 独立 Draft 2020-12 schema，随发行包提供，全部引用局限本文件 |
| [templates.py](../../decagent/business/plans/templates.py) | 将现有可信 Choice/Noul/Score 定义暴露为有版本目录；引用不能附加尺度或指令 |
| [compiler.py](../../decagent/business/plans/compiler.py) | 工具/版本/副作用类型、参数声明、引用来源、分支依赖、合流与完成证据的静态检查 |
| [bindings.py](../../decagent/business/plans/bindings.py) | 执行前解析真实输入；校验身份、来源、新鲜度、类型和最终工具 schema |
| [planner.py](../../decagent/business/plans/planner.py) | 可替换规划接口；默认复用现有直接模型连接；最多一次格式修复，预算层仍对实际请求记账 |
| [completion.py](../../decagent/business/plans/completion.py) | 结合目标、实际结果和持久回执判定成功；默认结果文本由代码生成 |

这些模块没有引入 Pi、向量数据库或新的模型服务。当前原模型接口继续使用原配置；实际调用只有接入运行器后才发生，本阶段测试没有请求付费模型。

## 计划边界

| 项目 | 当前界限 |
| --- | --- |
| schema_version | 字符串 1 |
| revision | 1–4，初始版本也计入 |
| 展开后的节点 | 最多 32 |
| 控制分支深度 / 条件嵌套 | 各最多 4 |
| JSON 深度 | 最多 32 |
| 计划 UTF-8 大小 | 128,000 字节，包含派生摘要 |
| 控制路径分析 | 最多 4,096 种待分析路径，超限拒绝 |
| 只允许的条件 | eq、in、exists、all、any、lt、lte、gt、gte |

节点类型为 read_tool、transform、decide、branch、join、ask_user、governed_write 和 complete。next 数组表示同时激活的后继；branch 的 cases 表示互斥路径。all_active 合流只等待实际激活的依赖。

## 五种参数来源

| source | 说明 | 解析前提 |
| --- | --- | --- |
| literal | 计划中的显式 JSON 常量 | 声明类型一致，仍通过工具参数 schema |
| task_input | 当前用户输入字段 | 字段路径存在，值符合声明 |
| node_output | 前序真实工具、纯计算或人工回答 | 与生产节点类型相符，已核实，员工和 scope 仍匹配 |
| accepted_decision | 已按策略或人工接受的 Jev 判断 | 接受标记有效，状态未过期，员工和 scope 匹配 |
| verified_memory | 经验证的当前员工记忆 | 活动、未过期、已核实且当前范围相符 |

每个绑定都有 value_type、nullable 和 provenance。字段路径是有限字符串/非负数组下标列表，不访问 Python 属性，也不执行表达式。

以下是前序创建结果的引用；它表达获取规则，不包含猜测的工单 ID：

~~~json
{
  "source": "node_output",
  "node_id": "create",
  "path": ["ticket", "id"],
  "value_type": "string",
  "nullable": false,
  "provenance": "tool_result"
}
~~~

write_receipt 来源只能指向 governed_write 的 receipt 字段，不能把 Jev 的建议包装成回执。分支中的可选值需要声明 nullable，并通过存在性判断或 coalesce 处理。未知值不能用占位文字替代。

当前注册纯计算为 identity、coalesce、normalize_title 和 priority_for_score。前者复制值；coalesce 选择第一个非空值，全部为空则请求补充；normalize_title 只清理两端空白；priority_for_score 复用原工作受阻尺度到 normal/high/urgent 的确定性映射。不存在 eval 或任意脚本入口。

## 可信问题与版本

当前复用 operation、explicit_assignee、multi_person、work_blockage，以及真实目录中的 person/category。程序保留原问题说明和评分尺子；动态候选来自当前 directory 结果。没有合法候选时给出缺候选出口，不制造 ID。

计划引用版本使用符合 schema 的形式，例如 1.0.0-business-1；这是现有 workflow/问题版本的规范化标识。问题目录本身不证明校准通过，条目均标 requires_matching_policy。实际自动判断仍要在后续策略阶段匹配模型解析版本和评测记录。

## 本地校验示例

[打包示例](../../decagent/business/plans/examples.json)包含只读目录，以及读取目录→Jev 选择分类→创建工单→核实回执。input_schema 描述调用者提供的字段，plan 内保留未来参数引用。

从 DecAgent 根执行下列校验，只编译示例，不请求模型或调用业务服务：

~~~powershell
@'
import json
from importlib.resources import files
from decagent.business.contracts import PluginSpec
from decagent.business.tickets import builtin_manifest
from decagent.business.plans.compiler import compile_plan

document = json.loads(
    files("decagent.business.plans").joinpath("examples.json").read_text(encoding="utf-8")
)
spec = PluginSpec.from_mapping(builtin_manifest())
for name, item in document["examples"].items():
    compiled = compile_plan(item["plan"], spec, input_schema=item["input_schema"])
    print(name, compiled.plan.digest, compiled.order)
'@ | python -X utf8 -
~~~

计划不能改写执行员工、传入凭据或自主批准操作。编译通过之后，真正执行前还需读取当前业务状态、检查权限、完成具体写入确认并核实回执。

## 模型与完成行为

ConditionalPlanner 输入结构化上下文，输出 PlanProposal。普通有效输出只需一次主模型请求；格式或静态校验失败最多修复一次；网络异常不在此适配层自动重试。父计划修订需有明确原因且 revision 连续，冻结区和原操作身份由持久仓库阶段再次验证。

默认返回结果通过真实证据渲染，不追加一次主模型生成结尾。模型自行声称完成、未核实写入、遗漏已执行写入或不同于原请求的操作，都不能通过完成检查。真实回执对照测试同时验证被修改的工作状态会被拒绝。

## 当前验证范围

- 契约、问题注册、编译、绑定、规划与完成的确定性测试。
- 真实 PostgreSQL 操作回执可用于完成证明，改动后的数据被拒绝。
- wheel 在源码目录外可读取 schema 与两份示例，且两份示例均能编译。
- 持久节点调度、工作台人工恢复和真实模型性能仍在后续任务中。
