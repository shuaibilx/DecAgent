# 阈值策略服务参考

## 状态与信任边界

| 项目 | 当前实现 |
| --- | --- |
| 服务 | [DecisionPolicyStore](../../decagent/business/policy_store.py)，可信服务端库接口 |
| 默认状态 | 没有预装验证报告、生产合格策略或默认 0.95 阈值 |
| 全局管理 | 已认证 OwnerIdentity；每次重新核对 owner 凭据或有效会话；业务 supervisor 不具备全局管理权 |
| 员工设置 | 原员工有效浏览器 EmployeeIdentity；重新检查账号、人员、会话、credential_revision 与任务归属 |
| 运行时解析 | 原员工有效浏览器或 MCP 身份；显式 policy_id 与 policy_version |
| 传输认证 | 调用端负责认证、Origin/CSRF 与请求解析；服务端再次核对持久身份凭据 |
| 报告真实性 | 受信 owner 负责核对来源、数据与人工复核证据；程序验证 schema、内容摘要、引用、版本和计数，无法凭 JSON 自行证明标签真实 |
| 实测声明 | 本次没有下载数据、付费评测或导入真实生产报告；测试报告仅为独立 case 数据库内的 schema/服务夹具 |
| 权限 | PolicyResolution 与 DecisionGate 均不授予写权限；参数、ACL、资源版本和具体写入确认仍需执行 |
| 缺策略 | 明确返回 policy=None 与 manual 原因；primary_fallback 始终为 false |
| 网关 | 本模块没有新增 HTTP 路由；后续网关对接属于独立实现 |

## 服务方法

| 方法 | 参数与效果 |
| --- | --- |
| register_validation(owner, report, expected_sha256) | 仅 owner 导入严格格式报告；expected_sha256 为 contracts.digest(report)，即 canonical_json(report) 的 UTF-8 SHA256；相同 ID 内容不同则拒绝 |
| register(owner, policy) | 仅注册 status=draft 的 ThresholdPolicy；引用已导入报告；question/version、primitive、实际模型与 PolicyContext 必须匹配，候选规模只能缩小 |
| publish(owner, policy_id, policy_version) | 再次验证报告与资格；过期版本不能发布；重复发布不重复记事件 |
| revoke(owner, policy_id, policy_version, reason) | 永久撤销该显式版本，保留报告、定义和历史；重新发布需新版本 |
| set_minimum(owner, policy_id, policy_version, threshold) | 对已发布有效版本提高管理员下限；已有版本不能下调；新值必须是合格实测阈值 |
| set_task_threshold(employee, task_id, policy_id, policy_version, threshold) | 原员工浏览器设置任务覆盖；必须是合格实测阈值，且不低于当前管理员下限；重复值不增加 revision |
| resolve(employee, task_id, policy_id, policy_version) | 返回 PolicyResolution；显式固定版本；首次生效或有效配置改变时追加任务事件；不改变 awaiting_input 等任务状态 |

## 验证报告格式

| 字段 | 约束 |
| --- | --- |
| format | decagent.decision-validation.v1 |
| report_id / reference | 有界非空标识及可追溯报告引用；报告内容不可改写 |
| binding.question_id / question_version / primitive | 问题与版本必须显式绑定；primitive 为 choice、noul 或 score |
| binding.actual_model | 已解析固定 Jev 版本；latest 等别名不能作为实际版本 |
| binding.context | 完整 PolicyContext：plugin_digest、workflow_version、dataset_version、risk、candidate_source、normalization_version |
| binding.min_candidates / max_candidates | 有界整数区间 2..256；包括 no_match、Noul 两个选项或 Score 档位；不能推导超出评测报告的范围 |
| dataset.version / split | 与 context.dataset_version 相同；split 必须为 validation，不能用 development 或 test 替代 |
| dataset.label_source / synthetic / human_reviewed | human-verified / false / true；synthetic 或未核对报告不能进入可信生产注册表 |
| dataset.reference / sha256 | 可追溯数据引用与 SHA256；由可信导入者核对实际数据 |
| dataset.review_reference / review_sha256 | 可追溯人工核对证据引用与 SHA256；不是模型自述或一次任务成功 |
| thresholds | 最多 32 个显式阈值记录；每条只有 threshold、n_auto、n_correct；阈值唯一、概率合法、计数为非负整数 |
| 合格阈值 | n_auto ≥100 且 n_correct/n_auto ≥0.95；整数交叉乘法判定边界；未达标网格行可以留存，但不能用于发布或任务覆盖 |

## 解析结果与后续门控

| 字段或步骤 | 含义 |
| --- | --- |
| policy | 当前可用 ThresholdPolicy，或 None；阈值为 max(管理员下限, 当前任务覆盖) |
| minimum_threshold / task_threshold | 分别显示当前管理员下限与任务选择，避免把二者混为一个历史值 |
| allowed_thresholds | 报告中仍达标且不低于下限的显式阈值；未发布、未来生效、过期或撤销时为空 |
| override_revision | 员工覆盖的递增版本；不重写既往语义决定 |
| effective_revision | 该 task/policy/version 有效配置的递增版本；首次读取为 1，重复读取同配置不增加 |
| reason | policy_available、policy_unavailable、policy_revoked、policy_not_yet_valid、policy_expired 或 policy_context_mismatch |
| gate_decision | 使用 resolve 返回的 policy，继续核对可信 QuestionSpec、实际模型、候选来源与规模、当前/原 DecisionSnapshot、normalization 及 certainty 阈值 |
| 动态快照 | state/candidate 摘要、scope/account ID 与版本只用于预测新鲜度，不能被当作已验证策略范围或操作授权 |
| 人工等待 | 提高阈值只影响后续待消费判断；已记事件、旧策略版本与原等待记录继续保留；回复恢复需后续人工待办服务重新验证 |
