# 员工范围业务记忆存储参考

## 范围

| 项目 | 已实现契约 |
| --- | --- |
| Workspace 范围 | 从当前已认证员工身份读取；不接受客户端指定 workspace。查询在读取内容前同时按 workspace 与员工过滤。 |
| 员工范围 | 主管身份也不会自动读取其他员工记忆；跨空间相同的 employee memory slot 仍分别解析。 |
| 当前性 | scope、account revision、contract/question/plan fingerprints 和 TTL 均匹配，且来源未撤销、仍能验证，才返回为候选。 |
| 候选数量 | `candidates` 默认且最多 8 条；最多检查 256 条已在 SQL 过滤的记录。 |
| 权限 | 记忆始终 `grants_write_authority=False`。当前业务权限、活动工单状态和审批许可不属于可存偏好 subject。 |
| 接线边界 | 通用规划不自动检索或注入记忆；只有已发布工作流按稳定槽读取。Jev 可筛选写入提议，不决定记忆读取。 |
| 旧记忆 | 不读取或写入 `app.memory_candidates`；仓库/Git/PR 合并激活规则不变。 |

## 类型和生命周期

| kind | 来源和激活条件 | 默认有效期 |
| --- | --- | --- |
| `confirmed_preference` | 同员工真实事件或成功回执；先保存 `pending_confirmation`；原员工当前浏览器会话确认精确 digest 后激活。 | 确认后 30 天 |
| `verified_workflow_experience` | 同员工已核实成功操作回执，以及当前 owner 已发布的固定提炼规则；内容由规则固定语句和真实 command/result 生成。 | 验证后 7 天 |

支持偏好 subject：`response_language`、`response_style`、`ticket_category_preference`、`communication_preference`。
偏好 content 固定为 `{value: 有界非空字符串}`，作为数据处理。
经验 content 固定为 `{command, outcome: succeeded, lesson: 已发布规则固定语句}`。
经验接口不接受模型编写的任意知识或自由文本结论。

状态：`pending_confirmation → active → revoked/superseded`。
过期是读取时判断，不通过再次读取或去重自动延长期限。
重复提交返回相同记录和期限；更正使用新的不可变记录及 `supersedes`。
新偏好确认和旧偏好失效处于同一事务；历史内容和审计保留。

## 当前上下文

`MemoryContext` 字段：`scope_id, scope_revision, account_revision, contract_fingerprint, question_fingerprint, plan_fingerprint, workspace_id`。workspace 由数据库验证的认证身份填入，并在每次 memory mutation / retrieval 时与当前身份比较；它不会出现在记忆 API 返回对象中。

`BusinessMemoryStore.context(identity, scope_id, *, question_fingerprint, plan_fingerprint)`
: 从数据库验证当前员工和注册契约，并建立不可变上下文。
  问题和计划指纹由可信运行时提供，不能把最终用户参数直接当作当前注册表事实。

`candidates` 返回 JSON 可序列化的记录，包含 `employee_id`、`scope_revision`、`account_revision`、`verified`、`active`、`expired` 和 `data`。
这些字段与 `verified_memory` 参数绑定契约一致。
候选只含记忆内容与证据引用，不含来源事件完整 payload、认证 token 或会话摘要。此接口供受控存储、写入提议冲突校验及本人历史管理使用，不是通用规划器的检索入口；正常读取必须走已发布计划绑定的稳定槽。

## 稳定槽读取

发布工作流声明 `memory_kind + subject`，例如 `confirmed_preference + response_language`。计划不得保存数据库 `memory_id`，用户输入也不能覆盖该声明。

运行时调用 `resolve_slot(identity, context, memory_kind, subject)`：SQL 先按当前 workspace、员工、业务 scope、账号/scope 版本、类型与 subject 过滤，随后检查 TTL、撤销状态、同空间来源和契约/问题/计划指纹。只有恰好一条当前有效记录会返回；零条返回不可用，多条抛出歧义错误。节点执行前再次解析；缺失、过期、撤销、来源失效、scope 变化或歧义都会暂停，绝不沿用缓存或让 Jev/规划器补值。

样例绑定：

```json
{"source":"verified_memory","memory_kind":"confirmed_preference","subject":"response_language","path":["value"]}
```

内部运行时 provenance 可以记录解析到的记录 ID 和内容摘要以便审计，但这些字段不属于发布模板或模型输入。

## 服务 API

| API | 行为 |
| --- | --- |
| `propose_preference(identity, context, *, subject, value, evidence_refs, supersedes=None)` | 校验真实来源，按内容、证据、范围和版本去重；不会自动确认。 |
| `confirm_preference(browser, context, memory_id, expected_digest)` | 复验原员工当前浏览器身份、来源和指纹；一次确认，重复调用不延长 TTL。 |
| `record_experience(identity, context, *, rule_id, rule_version, receipt_ref)` | 要求有效发布规则与同员工真实成功回执；缺规则或未知提交不激活。 |
| `candidates(identity, context, *, limit=8)` | 存储层受控使用：身份/范围/版本/TTL SQL 过滤后重新验证来源与规则；不用于通用 prompt 检索。 |
| `resolve_slot(identity, context, memory_kind, subject)` | 已发布工作流的精确稳定槽读取；返回唯一有效记录，否则返回缺失或歧义状态。 |
| `get(identity, memory_id, *, context=None)` | 仅本人历史。未提供当前 context 时，历史状态可查看，但 `active/verified=False`。 |
| `list_own(identity, *, context=None, limit=50)` | 本人有界历史列表，最多 100 条；提供 context 时限定 scope 并计算当前有效性。 |
| `revoke(browser, memory_id, expected_digest, reason)` | 原员工浏览器撤销；保留内容、来源和撤销审计。 |
| `revoke_source(browser, context, reference, reason)` | 撤回本人真实来源；所有依赖该来源的后续候选立即排除。 |

浏览器 mutation 的 CSRF/origin 检查由接入此服务的 gateway 继续负责；服务自身不接受裸员工 ID 作为身份。

## 来源证据

| reference | 实际检查 |
| --- | --- |
| `{kind: task_event, task_id, seq}` | 对应业务任务和事件真实存在；同 workspace、同员工、同 scope、契约一致。 |
| `{kind: operation_receipt, operation_id}` | 原操作 `succeeded`，workspace/scope/revision/contract 匹配，员工仍有命令权限和资源可见性；复用 `OperationService._receipt_evidence` 校验回执、资源、历史、实际参数和结果。 |

保存的引用额外带 `key`、真实来源 `fingerprint`、`employee_id`。
来源内容变化、撤回、当前权限失效、回执与历史不符均使记忆不可用。
伪造 ID、模型 `verified=True` 声明、历史 repair memory ID 不构成来源。

## 提炼规则

`publish_experience_rule(owner, context, *, rule_id, rule_version, command, lesson, validation_refs, valid_until)`
: 当前 owner 认证后发布不可变规则；至少一个同命令真实成功回执作为验证来源。
  首版 renderer 为 `verified-command-1`，只产生已验证操作结果与发布者固定语句。
  规则表默认空，不因一次成功或 Jev 建议自动发布。

`revoke_experience_rule(owner, context, rule_id, rule_version, reason)`
: 撤销当前 workspace 的已发布规则；其经验随即不再进入候选。规则键为 `(rule_id, rule_version, workspace_id)`，不同 workspace 可独立发布同名版本。

规则发布者负责固定语句的适用范围；该技术验证不代表统计正确率、跨场景因果结论或生产质量评测通过。
