# 游客与本机交付后续路线

> For agentic workers: 此文继承 guest-sop-local-trial 的已批准范围。进入每个子项目时用 openspec-apply-change 与 superpowers:executing-plans细化验收切片；当前不是一次性开放公网的授权。

**Goal:** 将通过工程验收的SOP Agent交付为隔离、限额、可恢复的本机游客体验。
**Architecture:** workspace贯穿可信身份与所有业务数据；游客生命周期、全站额度和Worker准入分别持久化。公共CI/GHCR仅产生可信产物，私有部署控制面才能调度本机Runner。
**Tech Stack:** 现有Python/FastAPI/PostgreSQL/MCP、Docker Compose、Windows本机Runner、GitHub Actions；真实浏览器E2E作为新增验收层。
**Spec:** [guest-sop-local-trial](../../../openspec/changes/guest-sop-local-trial/tasks.md)，原28项全部保持待办；本轮不虚增完成数。

## Global Constraints

- 游客无注册、独立模拟公司、同浏览器恢复、7天无活动过期、角色切换、清空；不支持跨设备找回。
- 北京时间日界：全站每日$5/500万Qwen Token；每游客30任务/50万Token；游客并行1、全站2、等待队列20。
- Jev未有合格阈值时仅给建议；语义选择与业务写入确认独立。
- 业务事实重新读取，跨任务记忆通过本空间当前员工和稳定槽解析。
- Qwen仍存在抵扣前账单；游客费率/日预算不得因代金券直接改成0。
- 本机短时中断可接受；域名、公网Tunnel及独立Linux验收后置。
- 游客数据/账本与公开benchmark隔离。

## Review Focus

- 相同subject/key跨空间碰撞：G1负向集成。
- 切换角色消费旧确认：G2真实浏览器E2E。
- 清Cookie、跨日、重启释放unknown：G3并发与恢复测试。
- API健康但Worker/MCP退出：D1业务探针故障注入。
- 公共工作流或任意dispatch输入获得本机执行权：D3来源验证与拒绝测试。

## G1：workspace身份与数据边界

关联1.1–1.6。先做空间基础，游客入口保持关闭。

涉及employee_auth.py、employee_accounts.py、access.py、tickets/store.py、任务/审批/operations/grants/receipt、gateway/business_trace.py、memory.py/memory_slots.py、mcp_client/server以及追加迁移；新增集中workspace解析模块，避免每处自行读取客户端参数。

- [ ] 先核对最高迁移号，追加workspace及legacy映射，不复用019或硬编码尚未确定的下一号。
- [ ] 迁移旧身份/任务/checkpoint/操作时保持原恢复语义；当前local-company固定约束须完整迁移。
- [ ] 所有数据访问从服务端身份取workspace，客户端不能覆盖；空间内supervisor不能跨空间。
- [ ] 两空间同名员工、同ticket/subject/key、猜ID、重放确认、trace/export及MCP都做负向集成。
- [ ] 验收旧员工与business-2恢复、重复迁移、业务schema权限与记忆撤销。完成后才能进入G2。

## G2：游客会话与生命周期

关联2.1–2.6。计划新增guest session服务和gateway路由，扩展现有工作台，不另造与生产执行器无关的演示。

- [ ] 创建/恢复与公司种子初始化原子化；Cookie、CSRF、Origin及本机/HTTPS行为一致。
- [ ] 角色切换清浏览器身份缓存；旧任务和待办仍绑定原员工；切换后不能消费旧确认。
- [ ] 7天无活动过期；后台轮询不续命；清空幂等且撤销凭证、停止新准入。
- [ ] 在途任务先取消/等待租约并核对unknown回执，再清业务记录与checkpoint；不因清空盲重放。
- [ ] Choice/Noul/Score、无匹配、补充、拒绝和独立写入确认均使用真实执行链；无合格阈值保持人选择。

## G3：日预算、并发、队列与限流

关联3.1–3.5。计划新增独立trial日账本/准入模块，复用实际模型派发的预留机制，不与benchmark共用额度。

- [ ] 精确实现既定全站/游客日额度和北京时间日界；Qwen账单费率、抵扣与实付按评测纠正口径延续。
- [ ] 模型请求同时经过任务/游客/全站原子预留；unknown跨日/重启保留，不因个人支付0而释放。
- [ ] 持久并发游客1/全站2、等待20；任务只在入队成功后计数。取消/满载/恢复不能双领取。
- [ ] 创建、提交和回复限流；仅可信代理解析转发头；清Cookie仍受全站约束。
- [ ] 并发数据库测试验证额度边界；UI真实显示等待、拒绝和unknown，不把未知费用显示成免费。

## G4：真正的本机浏览器体验

关联6.1及2.5。完成G1–G3后才在本机启用游客入口。

- [ ] 新增evals/e2e真实浏览器自动化，复用现有browser fixture而不是只跑Node DOM。
- [ ] 两个独立浏览器上下文覆盖创建/恢复、隔离、角色切换、人工选择、独立确认、记忆、限额、清空与重启。
- [ ] 使用脚本模型/受控Jev响应跑CI，零模型付费；少量真实模型体验单列证据，不替代公开benchmark。
- [ ] 保存失败截图/trace，稳定断言业务结果而非过度依赖页面文字；不将skip视为通过。

## D1：本机SOP部署与恢复

关联4.1–4.4。现有Compose仍运行repair worker，不能直接把历史部署称为SOP已上线。

- [ ] 新增SOP专用Compose与配置预检：API、业务Worker、业务MCP、PostgreSQL；仅loopback入口，repair兼容隔离。
- [ ] 业务探针覆盖Worker、MCP及可清理测试空间；注入Worker退出，证明API/health不能掩盖业务故障。
- [ ] 发布前保存旧digest/config/schema及备份；按不可变digest更新，健康失败且schema兼容时只回滚应用。
- [ ] 不兼容迁移停止并保留现场；禁止自动旧备份覆盖新数据库。
- [ ] 验证Windows登录、Docker Desktop/Runner/服务重启后的任务与额度恢复。用户接受关机/休眠的短时不可用。

## D2：代码仓库与公共CI

- [ ] 保留Python3.11/3.13、Ruff、确定性、独立PostgreSQL、wheel/MCP、Compose；新增真实浏览器核心job。
