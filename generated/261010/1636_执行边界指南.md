# DecAgent 执行边界与验证指南

创建于北京时间 2026-10-10 16:36。适用范围是用户认可的 Python 代码。普通 Docker 容器不提供对恶意代码、内核漏洞或容器逃逸的通用安全保证；允许公网访问也意味着项目内容可能被外发。

本次实现覆盖 executor-broker、固定 runner、安全工作区、执行凭据、HTTP/HTTPS 代理和 Compose 部署原语。当前 `compose.yaml` 启动 PostgreSQL、独立迁移 job、broker 和代理；完整 API/worker/网页编排仍需后续集成，不能把原语启动通过当作完整产品发布通过。

## 环境与实际验证

已实测 Windows Docker Desktop Linux engine 29.4.0，内核 `6.6.87.2-microsoft-standard-WSL2`。Docker socket 保留在 Linux broker 容器内，Windows 宿主不执行仓库命令。原 Waku、`decagent-apply-test-pg` 和已有用户卷没有被修改。

原生 Linux 宿主尚未实测，因此 OpenSpec 4.7 的双平台验收仍未完成。Linux 需要 Docker Engine 28+、正常启用 Docker 网络隔离规则以及支持 internal bridge 的 `gateway_mode_ipv4=isolated`。本实现不会在旧版本或自检失败时退回宿主执行。网络规则背景见 [Docker bridge 文档](https://docs.docker.com/engine/network/drivers/bridge/) 与 [Docker 网络过滤文档](https://docs.docker.com/engine/network/packet-filtering-firewalls/)。

## 固定运行环境和限额

Runner 使用官方 `python:3.11-slim@sha256:e88e9763f943ec1834f992a4b51e0f24500486803e8bc534e5767af9ea65f6ce` 基础镜像。`ops/runner/requirements.lock` 固定且检查 wheel SHA256：pip 25.2、uv 0.8.22、pytest 8.4.2、Ruff 0.14.3 及 pytest 的依赖。镜像还包含不可由仓库覆盖的 `decagent_check` 检查模块。仓库自己的依赖必须另外按其 requirements/lock 准备；runner 的工具锁不能替代项目锁。

从 DecAgent 根目录构建并获取本机不可变镜像 ID：

```powershell
docker build -f ops/runner/Dockerfile -t decagent-runner:local .
$env:DECAGENT_RUNNER_IMAGE = docker image inspect decagent-runner:local --format '{{.Id}}'
```

Linux 使用相同 build 命令，然后 `export DECAGENT_RUNNER_IMAGE=$(docker image inspect decagent-runner:local --format '{{.Id}}')`。每个 reproduction bundle 必须记录当次镜像 ID；broker 拒绝未固定 digest 或缺少版本标记的镜像。

每次命令使用新容器和对应任务的独立工作卷/只读基线卷：uid/gid 10001、全部 capability drop、no-new-privileges、Docker 默认 seccomp、只读根目录、256 MiB tmpfs、2 CPU、4 GiB 内存、128 pids、1024 文件描述符。普通命令最多 120 秒，明确绑定的 setup 命令最多 600 秒；可以采用更短超时。输出默认 64 KiB，上限 1 MiB。安装目标应是工作区内的 `.venv`，镜像系统 site-packages 只读。

Windows Docker Desktop 的 VM 资源还需为数据库、broker、代理和每个并发 4 GiB runner 留出余量。不能仅凭界面显示分配了内存就声称所有任务资源限制通过；集成测试读取 runner 的 cgroup 限额并检查 Docker inspect。

## 工作区、基线和凭据

Archive 只接受受限 tar/tar.gz，拒绝绝对路径、父目录、Windows drive/ADS、符号链接、硬链接、特殊文件、重复条目、文件作为父目录，以及 `.env`、SSH/Git/控制秘密路径。输入/源码快照上限 50 MiB、20,000 条目。工作区读写和 diff 按任务 lease 串行；写 helper 使用 no-follow 文件描述符。基线卷由创建 receipt 固定，并在命令容器中只读挂载。

源码快照通过固定 helper 的 Docker exec stream 返回，关闭该 helper 容器的日志。`.venv`、`.cache`、`__pycache__`、pytest/Ruff caches 不进入源码 diff/快照。源码中的链接、特殊文件或超限会明确阻塞。内部 `/v1/workspaces/snapshot` 返回 tar base64 与 tree hash，疑似凭据内容在编码前被阻止，不能把这类内部原始树 DTO 直接放入模型或界面。

任务环境没有模型密钥、PAT、数据库密码、broker token、宿主目录、Docker socket 或其他任务卷。服务秘密由 Compose secrets 文件或控制服务配置提供。命令输出由可信 PID 1 supervisor 先收集完整行、截断、用统一 Redactor 处理，然后才写 Docker 日志和 receipt。过长的整行会丢弃，避免截断产生凭据残片。识别常见凭据模式属于防御措施，不保证识别任意混淆秘密。

## Broker 接口与恢复

Broker 的所有接口包括 `/health` 都要求 `Authorization: Bearer <内部服务 token>`，token 至少 32 字符。Compose 不映射 broker 或数据库宿主端口；只有 broker 挂载 Docker 管理 socket。固定 runner 和 proxy 是受信任基础设施，服务 token 只能交给授权 worker。

请求统一携带 canonical UUID `task_id`、`owner`、正整数 `lease_generation`。执行请求另含 `action_id`、`execution_id`、`action_digest`、`argv`、`cwd`、`kind`、`timeout_seconds`、`max_output_bytes`。不接受 env、Docker 参数、宿主路径或任意资源配置。Broker 锁定数据库 task/action，校验 owner/generation/有效期和 action 所属任务，并匹配已持久化的参数。setup 还需要 action snapshot 的 `execution_kind="setup"`。审批与代码信任由控制服务在 dispatch 前持久化并检查；服务凭据不能替代这些授权。

内部 POST 接口：`/v1/workspaces`、`/v1/workspaces/read`、`/v1/workspaces/write`、`/v1/workspaces/diff`、`/v1/workspaces/snapshot`、`/v1/executions`、`/v1/executions/status`、`/v1/executions/cancel`。Workspace 创建使用 `archive_base64`；写文件使用受限相对 `path` 和 `content_base64`。文件读取返回脱敏 text，diff 也先脱敏。

同一 execution ID 和完全相同参数复用既有 receipt，内容不同返回冲突；同一 action 不能换 execution ID 再次执行。Receipt journal 持久化于 broker 卷，并与 `app.action_attempts` 关联。`completed` 只表示命令已退出，是否修复成功必须由独立验证层判断。退出码非零也可以有 completed receipt。

取消、超时或 lease 失效会停止整个容器及其进程。原 lease 失效后新 owner/generation 可以查询原 execution receipt；不能用新 generation 将原执行请求重发。broker 重启会核实已结束容器，停止仍运行的旧容器，未确认启动/结果保留 `result_unknown`，不会自动重放。未确认的工作区创建保留 immutable digest 并阻塞，需人工/管理端核查，不能用新 archive 覆盖基线。一个 journal 卷仅允许一个 broker 实例持有锁。

## 公网协议与启动自检

任务网是独立 internal bridge，启用 isolated gateway mode，IPv6 直连关闭；broker/API/数据库不加入任务网。无凭据代理加入每个任务网和自己的公网网络，IPv4/IPv6 forwarding 均关闭。

公网只支持 HTTP 80、HTTPS 443 和 CONNECT 443。CONNECT 是 TLS 隧道，HTTPS 客户端负责证书验证。FTP、SSH、自定义端口、HTTP upgrade、chunked upload、凭据 URL、单标签/内部域名等会被拒绝。pip/uv 如需连接其他端口或协议，应报告不支持，不能扩大 Docker 权限或关闭边界。

代理每次连接重新解析 DNS，验证全部地址后固定 literal IP 连接，不允许连接层第二次解析。拒绝 loopback/private/link-local/multicast/shared 地址、云元数据、IPv4-mapped IPv6 和常见地址转换/隧道网段。HTTP 连接一次只转发一个请求，redirect/重连均重新检查；HTTPS redirect 后的新 CONNECT 同样重新检查。

启动及新任务网自检实际运行固定 runner：公网 HTTP 与 PyPI HTTPS/CONNECT 成功；公网 IPv4/IPv6 直连失败；私网、host/gateway.docker.internal、metadata、mapped IPv6、控制主机名经代理被拒绝；真实数据库/broker 地址不能直连。任何检查失败，broker 不 ready 且仓库命令不可启动。控制网络容器名可通过 `DECAGENT_CONTROL_CONTAINERS` 设置，不能省略实际控制平面目标来冒充边界通过。

## 一次性 Compose 原语检查

在 DecAgent 根目录运行：

```powershell
.venv/Scripts/python.exe ops/executor/evaluate.py
```

Linux 用 `python ops/executor/evaluate.py`。脚本检查专用测试 project 没有既有容器/卷，生成临时服务凭据，构建 runner，按 `compose.yaml` + `ops/executor/compose.test.yaml` 启动专用实例，等待数据库与迁移后验证 broker health 中的真实边界检查。它仅清理该次创建的 `decagent-executor-compose` 资源和带对应 instance 标签的临时 probe，不使用 prune，也不删除生产数据。输出 `compose_primitive_boot=passed` 只表示这些原语通过。

生产原语启动前，应在 `.decagent/secrets/` 分别创建随机 `broker_token` 和 `postgres_password` 文件，配置镜像 ID，然后运行 `docker compose up --build -d`。不要把这两个秘密文件放入仓库或任务 archive。完整网页工作流等待 API/worker 编排完成后按对应产品指南验证。

## 确定性与真实容器测试

确定性检查：

```powershell
.venv/Scripts/python.exe -m pytest evals/deterministic/test_executor_boundary.py -q
.venv/Scripts/python.exe -m ruff check decagent/executor ops/runner ops/executor evals/deterministic/test_executor_boundary.py evals/integration/test_executor_docker.py
```

真实集成测试文件为 `evals/integration/test_executor_docker.py`，需要 Linux 测试容器中的 Docker socket、`DECAGENT_EXECUTOR_INTEGRATION=1`、专用 `DECAGENT_TEST_DATABASE_URL`（hostname 必须为 decagent-executor-pg）、`DECAGENT_RUNNER_IMAGE` 和 `DECAGENT_PROXY_CONTAINER`。无服务时显式 skipped，不能计为通过。测试数据库必须与生产/其他测试数据库分开。

本次已验证：56 个确定性 case；12 个真实 Docker/SQL case（48.50 秒）涵盖退出码与 cgroup/inspect、重复 count=1、普通/setup 超时终止子进程、取消整个容器、lease generation 变更 fencing、只读 baseline、symlink 写拒绝、输出在 Docker logger 前脱敏/截断、同一 action 换执行 ID 拒绝、环境缓存不进入 diff、公网 302 重定向到 metadata 后被代理拒绝，以及真实不可用代理导致 broker 保持禁用。Compose 专用新实例已通过 PostgreSQL -> migrate -> broker 启动与全部实际边界检查，并删除了其一次性数据。

DNS 混合答案、重绑定第二次解析和地址固定采用确定性协议测试验证；公网可用性与隔离采用上述真实容器检查。这不等同于在真实攻击者控制的 DNS 域名上进行了互联网 DNS 重绑定实验。原生 Linux、完整 API/worker/网页和真实仓库发布闭环仍需各自单独验收。
