## 官方协议核对

2026-10-10 核对 [TypeSafe API](https://docs.typesafe.ai/api)、[Confidence](https://docs.typesafe.ai/confidence) 和 [Models](https://docs.typesafe.ai/models)：

- 独立调用 `POST https://api.typesafe.ai/v1/systemone`，使用 Bearer 密钥以及 `model/state/questions`；Jev 不承担代码、事实或解释生成。
- 用户选择 OpenRouter 时，调用 `POST https://openrouter.ai/api/v1/decisions`，仍使用结构化 Decisions 协议；请求模型为 `~typesafe/jev-latest`，不发送到普通 chat completions。参见 [OpenRouter 官方说明](https://openrouter.ai/blog/insights/what-is-jev/)。
- Choice 返回 `type/choice/probabilities/confidence`，包含提交选项的完整概率分布。Noul 返回 `type/noul`，没有独立 confidence。
- 返回 `model` 表示实际模型。已执行的 OpenRouter 诊断解析为 `typesafe/jev-1.13-20260917`。别名会随服务更新而移动，旧校准不自动适用于新版本。
- 概率及供应商 confidence 都不等于在本项目上的实测准确率。

模型 ID 可配置。价格没有写死；OpenRouter 的合法 `usage.cost` 用于结算。供应商没有返回金额时，只使用显式价格依据，否则保留未知费用预留。

Choice confidence 根据完整分布校验：`(最大概率 - 1/选项数) / (1 - 1/选项数)`。这衡量分布集中程度，不是业务准确率。比如三个选项的最高概率为 0.98，confidence 为 0.97；Noul 仍只有 yes 概率。

## 独立配置与同步 API

控制服务 `Settings.from_env()` 自动读取当前项目根目录 `.env`，已有进程环境变量优先。worker 读取独立的 `DECAGENT_JEV_API_KEY`、`DECAGENT_JEV_MODEL`、`DECAGENT_JEV_PROVIDER=openrouter`；适配器自身不隐式加载配置或启动诊断。缺密钥或缺显式预算时，`JevAdapter.evaluate()` 返回 `missing_key` 或 `missing_budget`，没有网络请求。Compose 使用受保护的 secret 文件，只给 worker 挂载模型密钥。

```python
from decagent.decisions import (
    CallBudget, DecisionContext, DecisionEngine, JevAdapter, build_request,

context = DecisionContext(

    code_version="workspace-tree-sha256", evidence_version="evidence-sha256",
    policy_version="policy-1", authorization_version="authorization-sha256",

request = build_request(("action_risk",), {
    "action": {"tool": "write_file", "path": "src/main.py"},
    "authorization": "User authorized local changes in this task",
    "risk_features": ["local write"], "code_excerpt": "sanitized relevant excerpt",

# A caller provides a separately authorized key and a reviewed spend reservation.
# This example does not initiate a request merely by importing the module.
budget = CallBudget(max_usd=0.10, reserve_usd=0.03)
```

`build_request(question_ids, evidence, context)` 只选择相应问题允许的字段，并冻结输入副本。版本信息留在本地记录，完整原始任务不会自动传给服务。字段超过 128,000 UTF-8 字节或含 NaN 等非法 JSON 值时拒绝。调用者仍负责提供已脱敏的最小片段，以及校验材料来源。

| 问题 | 结果空间 | 必需输入字段 | 可选输入字段 |
| --- | --- | --- | --- |
| `action_risk` | `allow / deny / review` | `action, authorization` | `risk_features, code_excerpt` |
| `intervention` | `continue / clarify / review` | `goal, observations` | `blockers, next_steps` |
| `task_intervention` | `continue / replan / clarify / escalate` | `goal, attempts, progress_signals` | 无 |
| `memory_write` | `retain / discard / review` | `candidate, source_evidence` | `confirmation_refs, conflicts` |
| `memory_read_needed` | Noul 概率 | `task_summary, current_version` | `search_terms` |
| `memory_relevant` | Noul 概率 | `task_summary, current_version, candidate_summary` | 无 |

相互独立且共享同一证据的问题才适合批量请求；调用者负责这一语义判断。一个 Noul answer 只有 `.probability`；Choice answer 有 `.choice/.probabilities/.confidence`。答案和请求不能通过原始字典的后续修改改变。

新版工具提议只请求 `action_risk`。旧 `intervention` 用于历史双问题记录兼容，不能把旧问题的校准应用到新 `task_intervention`。新问题在处理完工具结果且出现重复观察或连续失败时独立请求，避免每个普通动作都做人工介入判断。

`InterventionCoordinator` 保存 Jev 原建议和程序实际路由。新问题没有真实校准时，建议只供观察；规则会继续、发出最多两次调整提示或提交证据化求助。请求失败同样保留错误依据并按有界规则处理；结果未知的工具先核实。有效的人类新线索开始新的局部调整周期，总预算和原权限不变。详见[介入流程与恢复](../261011/0616_智能体架构详解.md)。

`DecisionEvaluation` 保存请求模型、实际模型、上下文版本、输入哈希、字段名摘要、问题版本、合法答案、每次尝试及错误码。`DecisionResult` 另存实际 `routes/governance_outcome/reason`，与模型建议分开。`.to_dict()` 输出可以 JSON 序列化的记录，省略原始证据、密钥和异常字符串。

## 超时、重试与预算

默认每次尝试 10 秒，最多两次重试，即最多三次网络请求。只对明确的 429、529 和 5xx 响应进行有限重试；transport 超时或连接中断可能已产生费用，因此不立即重试。401、422、其他客户端错误、重定向和非法响应不重试。退避为 0.5、1.0 秒，加 0–0.25 秒抖动；不会跟随重定向发送 Bearer 密钥。

每次请求前调用 `AttemptBudget.reserve(request, attempt)`，返回正数美元预留或 `None`。每次实际尝试后调用 `settle(AttemptRecord)`。预算接口异常会失效降级；使用量审计 hook 失败也不会返回可自动采用的结果。自定义持久预算适配器必须将预留与任务绑定，并在请求前持久化。

`CallBudget` 是简单的本地预算实现：未知 usage 或未配置价格时把整份预留计入已占用金额；不能把超时当作免费。合法 usage 可以经显式 `cost_estimator(Usage) -> float` 结算。实际金额超过单次预留时仍记录金额，但结果失效并返回 `budget_error`。预留必须覆盖服务可能收取的上限；生产数据库预算可对未知调用保持未结预留，直到人工或账单核实。

可注入 `httpx.Client`、`sleep`、`jitter`、单调 `clock`、UTC `utcnow`、`usage_hook` 和 `cost_estimator`。注入 client 的生命周期由调用者管理；适配器自行创建的 client 由 `close()` 或上下文管理器关闭。

## 保守策略与缓存

`DecisionStrategy.evaluate(request)` 是 rule/main-llm/jev 的统一纯判断接口。`RuleStrategy` 对语义问题保守转审核。`MainLLMStrategy` 接受已单独计费的同步 classifier，复用严格答案格式；它自身没有模型 HTTP 调用，classifier 的密钥、usage 和预算由上层处理。

`DecisionEngine.decide(request, hard_outcome="semantic")` 默认让所有未校准语义问题进入 `review`，即使模型 confidence 很高。可信确定性策略可以传入 `allow` 或 `deny`，直接跳过判断服务；策略替换不能改变这个硬结果。引擎检查策略结果是否绑定当前输入、问题和上下文。

只有匹配实际模型、问题版本、数据集版本和策略版本的唯一 `CalibrationPolicy` 才能采用对应自动路由。Choice 根据供应商返回的 confidence 阈值路由；Noul 根据概率的正负两端路由，中间区间审核。引擎始终设置 `automatic_memory_enabled=False`：`retain` 只是候选建议，实际记忆激活仍需要合并、来源、确认和冲突等独立治理。

缓存绑定项目、输入哈希、问题内容/版本、输入格式版本、代码、证据、授权、策略、数据集及请求/实际模型。固定模型可在同项目且所有材料相同时跨任务复用；别名缓存限定同任务。默认有效期 300 秒、最多 256 项；到期重新解析版本，未匹配新模型的旧校准不会生效。缓存命中没有新 attempts，避免重复计费；数据库需单独保存缓存复用事件。

硬授权、发布门槛、活跃记忆过滤及执行前重查属于上层治理责任。这个模块只返回判断及程序路由，不执行工具，不创建审批，不激活记忆。

`durable_decide()` 在 HTTP 调用前提交数据库意图。节点重入复用原答案；已发出但没有持久结果的调用转审核，不再次收费。采用答案前重查当前代码、证据、授权、策略和校准阈值。仅调整阈值时，对原分布重新路由；改变问题或材料时建立新判断。

持久判断 ID 已包含任务及完整请求版本上下文。两个任务的相同观察分别保存意图，完全匹配的旧版 ID 仍可恢复。旧合成校准夹具只拟合其实际包含的问题；不会为新增问题制造标签。`intervention-report` 导出的新样本也保留 `human_label=null`，无法据此宣称决策准确率。

## 人工样本与校准格式

`SourceManifest` 保存来源 ID、HTTPS URL、许可证 ID 和用途说明。它验证格式，不代替真实许可核查。`HumanSample` 保存样本 ID、题目/版本、输入 SHA256、来源、泄漏分组、`calibration/holdout`、可空人工标签及 labeler。Choice 标签只能是声明选项，Noul 标签只能是布尔值。未完成标签必须写 `null`，不得把模型结果写成人工标签。

`HumanDataset` 的格式版本为 `1`，包含数据集版本、来源和样本；拒绝未知来源、重复 ID，以及输入哈希或 leakage_group 在校准集和保留集之间重复。`to_dict()/from_dict()` 用于 JSON 保存和导入。格式支持工具风险、介入、记忆写入和记忆读取四类问题。

`calibrate(dataset, question_id, actual_model, predictions, policy_version=..., max_error_rate=0, min_accepted=1)` 只读取相应题目的校准集人工标签和固定模型预测，选择满足接受样本数及校准误差上限的最低观察阈值。保留集预测不参与阈值拟合。缺标签、预测、版本匹配或可用阈值时拒绝导出；不根据未标注模型输出来制造阈值。

`export_calibrations()` 与 `load_calibrations()` 输出/导入版本化策略配置并拒绝重复绑定。阈值记录校准样本 ID、实际模型、问题、数据集和策略版本。小样本得到的经验阈值不构成安全证明，需要另用保留集和真实业务数据评价。
