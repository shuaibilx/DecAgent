## 验证范围

网关提供拥有者认证、持久化 API、静态网页和 CLI 客户端。网关只向数据库排队，读取持久化证据，并调用明确注入的受信任控制服务；它不直接执行宿主命令、调用模型、管理 Docker 或发布 GitHub 内容。

本指南创建时，网关相关 27 项测试分别通过 Windows Python 3.13 和 Linux Python 3.11，并使用真实 PostgreSQL。独立 loopback 实例的实际浏览器检查覆盖登录、仓库登记、任务提交与取消、批准/拒绝/编辑、澄清、预算恢复、记忆审核/撤销、配置和本地诊断。浏览器中的任务、差异、等待状态和 PR 链接明确标为 OFFLINE FIXTURE；它们验证 UI 与数据库行为，不代表真实修复、执行器、模型调用或 GitHub 发布已经完成。

下面的完整 CLI 命令及 worker 装配由主实施线程接入，创建本指南时尚未完成其最终联调；需在根线程验收后补充本节。HTTPS 的规则已有接口测试，真实域名、反向代理与证书部署尚未实测。

## 本地配置与初始化

从 DecAgent 根目录安装依赖，创建受本地权限保护的 `.env` 或使用 Compose secrets。`.env.example` 保留占位值；不要把真实密钥写入模板。已有进程环境变量优先于项目 `.env`。

必要或常用变量：

| 变量 | 用途 |
| --- | --- |
| DECAGENT_DATABASE_URL | 控制数据库连接，仅控制服务持有 |
| DECAGENT_DATA_DIR | 独立的 DecAgent 数据目录，默认 .decagent |
| DECAGENT_PUBLIC_URL | 精确工作台 Origin，默认 http://127.0.0.1:8000 |
| DECAGENT_MAIN_BASE_URL / DECAGENT_MAIN_MODEL | 主模型地址和模型名称 |
| DECAGENT_MAIN_API_KEY | 主模型密钥 |
| DECAGENT_JEV_PROVIDER | typesafe 或 openrouter |
| DECAGENT_JEV_MODEL / DECAGENT_JEV_API_KEY | 独立决策模型和密钥 |
| DECAGENT_GITHUB_TOKEN | 服务端 GitHub 凭据 |

更换模型、Jev 或 GitHub 密钥后重启控制服务。读取配置接口只返回模型信息及密钥是否已配置。拥有者登录令牌与这些供应商密钥是不同凭据。

预期完整 CLI 启动顺序：

```powershell
python -m pip install -r requirements.txt
decagent migrate
decagent init
decagent doctor
decagent serve --host 127.0.0.1 --port 8000
```

另开终端运行 `decagent worker`，由 worker 处理队列。缺少模型、数据库、GitHub、执行器或当前策略服务时，应按诊断结果补齐；“已配置”不代表外部连接或执行边界已经验证。

初始化将高熵拥有者令牌写入默认 `.decagent/owner.token`，输出仅应包含文件路径。数据库只保存 SHA-256 摘要。Linux 文件权限为 0600；Windows 在写入内容前取消继承，仅授予当前拥有者与 SYSTEM。再次初始化会拒绝替换已有拥有者凭据，也不会覆盖已有文件。保存好原凭据文件；数据库备份不包含它的明文。

## 网页工作流

1. 打开与 DECAGENT_PUBLIC_URL 完全一致的地址，用本地拥有者令牌登录。令牌不会写入浏览器持久存储；网页会保存非凭据的 CSRF 值用于当前会话。会话默认 12 小时，到期需要重新登录，退出立即撤销。
2. 在“登记仓库”填写 `owner/repository` 和默认分支。查看真实权限诊断状态；未连接权限诊断时，结果为 unverified。
3. 选择项目，填写基准提交或分支、问题、复现与验收要求，设置调用/Token/活动时间/费用上限。离线或缺少基准解析服务时，只接受精确 40 位 SHA。价格未知时需要明确勾选受调用和 Token 上限约束的运行意图。
4. “申请执行当前精确提交”只保存请求范围，不在提交时自动授予代码信任。具体 SHA、代码来源、分支范围和当前策略仍需通过版本绑定的代码认可。
5. 是否允许草稿 PR 是单独、明确的提交授权。未选中时不会授予发布许可。真实发布还必须满足复现、验证、内容匹配和 GitHub 门槛。
6. 最近任务展示持久化状态与阶段；事件连接状态单独显示。浏览器重连从任务 seq 继续，断线不会重启任务。切换任务保留已显示事件，页面刷新可以重新读取完整持久化事件。
7. 差异与验证记录都是读取结果。没有证据时分别显示 unavailable / unverified，不把空记录当作通过。判断记录展示程序路由、模型结果、版本及证据。
8. 等待页面显示具体缺失信息、当前证据和所需动作。澄清与验收使用明确确认内容；模型文本、日志和记忆不能替代拥有者确认。
9. 审批时检查动作参数、目标、摘要、版本和判断依据。可批准、拒绝，或编辑动作参数后重新治理。编辑不会批准旧动作；硬拒绝会显示具体原因，历史保留编辑后的判断。
10. 回复保存后使用“重新校验并恢复”。尚未回复的审批、终态任务、过时授权或过时动作审批会返回冲突。预算暂停需提供新的完整预算；外部结果未知时需先核实回执。
11. 查看交付状态和 PR 链接。合并由拥有者在 GitHub 完成，工作台不会自动合并。
12. 在“项目记忆”检查来源、证据、适用版本和冲突，写明具体审核确认后申请激活或拒绝；撤销按当前修订执行。审核不能跳过代码知识的真实合并和证据门槛。

取消排队任务可直接持久化取消。运行或恢复中的任务必须由受信任取消服务确认执行器已停止，再清除租约并取消；缺少该服务时返回 unavailable。网关不会把未确认的进程状态显示为停止。

## CLI 与同一套授权

主线程约定的完整操作形式如下，最终安装后可用 `decagent --help` 和子命令帮助核对：

```powershell
decagent tasks
decagent task submit --project-id PROJECT_UUID --base-ref EXACT_SHA --issue "问题和验收要求" --max-cost 1.00 --trust exact_commit
decagent task show TASK_UUID
decagent task cancel TASK_UUID
decagent task resume TASK_UUID --max-cost 1.00
decagent backup backups/instance-unique-name
```

只有明确要发布的任务才添加 `--publish-draft`。其他预算参数及恢复要求以子命令帮助为准。

网关客户端已可独立使用，真实 token 从本地受保护文件读取，不作为命令行参数或 URL：

```python
from pathlib import Path
from decagent.gateway import OwnerClient

with OwnerClient("http://127.0.0.1:8000", Path(".decagent/owner.token")) as client:
    task = client.task("TASK_UUID")
    tasks = client.tasks()
    # client.cancel("TASK_UUID")
    # client.resume("TASK_UUID", budget={"max_calls": 40, "max_tokens": 120000})
    local = client.diagnostics(mode="local")
```

CLI 使用 Bearer 认证调用相同 API；它没有绕过审批、策略或执行器边界的任务操作。任务恢复会重新校验已批准动作的当前摘要。客户端拒绝远程 HTTP 和重定向，错误信息经过脱敏。

`migrate` 使用版本化迁移。`backup` 的目标必须是新目录，已有文件不被覆盖。`restore` 只用于另一个新建空数据库和证据卷；生产数据库、原凭据文件和故障证据应保留。备份与完整 CLI 联调的实测状态由主实施线程补充。

## 本地与真实诊断

“运行本地诊断”只检查控制数据库可达和本地凭据配置状态，返回 `external_requests: 0`；模型为 not_contacted，执行器与 GitHub 权限保持 not_verified。

真实诊断必须选择一个服务，并勾选“确认这一次受限真实诊断”后点击按钮。只有明确注入的诊断服务执行该请求；未装配时返回 integration_unavailable，不模拟成功。模型诊断可能产生费用，应设置用户授权的费用上限。页面载入、刷新、读取配置和本地诊断不自动启动真实诊断。

## HTTPS 与 loopback

开发 HTTP 只允许 `127.0.0.1`、`localhost` 或 `::1`。Origin 必须与 DECAGENT_PUBLIC_URL 精确一致；localhost 与 127.0.0.1 不能混用，端口不同也会拒绝网页登录或写操作。

远程实例把 DECAGENT_PUBLIC_URL 配成完整的 `https://你的域名` Origin，不包含路径、查询或凭据。使用 TLS 反向代理，并只信任已知代理的转发头。API 必须看到 HTTPS 请求；不能靠开放所有来源、禁用 CSRF 或信任任意客户端转发头解决部署问题。

网页 Cookie 为 HttpOnly、SameSite=Strict，HTTPS 实例附加 Secure。所有浏览器状态变更都校验 CSRF 与精确 Origin。没有 CORS 放行。CLI Bearer 写操作没有浏览器 Cookie 的 CSRF 机制，但带 Origin 的 Bearer 请求仍必须来自精确 Origin；HTTPS 实例拒绝明文 HTTP 的 API 请求。

## API 复用与联调契约

所有拥有者数据接口位于 `/api/v1`。健康检查仅返回 `{"status":"ok"}`。错误统一为 `code / message / task_id / details`，不回显验证输入或供应商错误正文。

业务创建和状态变更要求 Idempotency-Key。作用域为拥有者、HTTP 方法与精确端点。同一键相同内容返回已保存响应；同一键不同内容返回 409。业务 SQL 变更、审批记录、事件和响应在同一事务内提交。注入的外部取消、核实及诊断服务另外接收稳定 operation_id，用于自身回执与幂等核实；数据库事务不能保证外部副作用 exactly-once。

SSE 使用任务 seq，支持 Last-Event-ID 和显式 `?after=N`。联调可用 `?follow=false` 读取有限历史。事件由数据库读取并再次脱敏，不由连接状态推导任务执行状态。

装配入口：

```python
from decagent.gateway import create_app, GatewayCallbacks, initialize_owner

app = create_app(database, settings, callbacks=GatewayCallbacks(
    current_policy_context=current_policy_context,
    memory_manager_factory=memory_manager_factory,
    cancel_task=cancel_task,
    reconcile_task=reconcile_task,
    live_diagnostic=live_diagnostic,
    resolve_base=resolve_base,
    project_diagnostic=project_diagnostic,
))
```

回调契约位于 `decagent/gateway/app.py`。缺失回调明确不可用。memory_manager_factory 接收 project_id 和加入当前 API 事务的 scoped_database；它必须使用真实 MemoryManager。策略上下文从当前可信任务状态装配，不能反序列化请求中的授权或代码信任。

代码认可审批的 pending reply_payload 保存纯 code_trust_request，摘要由 CodeTrustRequest.digest(context) 计算。批准后，issue_code_trust、审批消费与 authorization_snapshot.code_trust 同一事务提交。动作审批通过 DurableApprovals 处理并验证当前 action_digest；编辑后的参数必须重新治理。任务 UUID 在授权快照之前生成，授权包含 id/version、任务/项目/仓库、active、publish_draft 和认证 owner provenance。

worker 持久化 `repair.diff`（或 diff/workspace.diff）事件供差异页读取，并持久化 `task.waiting` 的 reason/question 等内容。没有记录时网页仍显示缺少证据。

## 离线浏览器复查

独立测试实例使用新的 PostgreSQL 数据库，不清空现有测试或用户数据库：

```powershell
# DECAGENT_TEST_DATABASE_URL 指向专门的离线测试管理员数据库
python -m evals.integration.test_gateway_browser_fixture
```

打开 `http://127.0.0.1:8021`。该文件含公开的、只用于新建本地 fixture 数据库的测试登录值；不得用于真实实例。manifest 保存在 `output/playwright/browser-fixture/manifest.json`，任务均带 OFFLINE FIXTURE 标记。测试退出时停止该独立服务器；历史数据库保留，不提供默认删除命令。

2026-10-10 的实际浏览器检查验证了：代码编辑越界时显示“Parent traversal is forbidden”、审批历史保留 hard_denial；切换后同一任务仍显示 seq 1/2/3 三条既有事件，未重复创建任务；提交新任务显示 queued，取消后显示 cancelled；澄清、预算暂停及记忆操作有明确入口。真实模型修复、受限执行器、HTTPS 部署和真实 GitHub 交付应分别报告实测证据。
