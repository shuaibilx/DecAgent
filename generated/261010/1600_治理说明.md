# DecAgent 治理说明

创建时间：北京时间 2026-10-10 16:00，读取可靠 UTC 时钟后转换。

`decagent.policy` 是不执行工具、不连接模型、不提供进程内审批库的纯治理层。它将模型提出的动作和控制服务加载的任务上下文分开；数据库事务、登录认证、执行 broker 和真实模型接入仍由控制服务负责。原 Waku 与 `.waku/` 不属于可编辑或可访问的任务工作区。

## 接口与来源边界

主要接口：

| 接口 | 用途 |
| --- | --- |
| `Action(tool, params)` | 接收工具提议；深拷贝为不可变映射和元组 |
| `PolicyContext` | 可信服务加载任务、仓库、代码快照、授权、策略与边界证明 |
| `govern(action, context, approval=None, semantic_advice=None)` | 返回 allow、deny、review 或 code_trust_required |
| `action_digest(action, context)` | 生成 SHA256 摘要；摘要本身不授予执行权 |
| `reply_to_approval(record, reply, action=None, context=None)` | 产生不可变的一次性审批回复状态 |
| `consume_approval(record, digest, execution_id)` | 将已批准动作/代码认可绑定到一次持久化操作 |
| `CodeTrustRequest.digest(context)`、`issue_code_trust(...)` | 绑定当前代码认可并生成版本化范围 |
| `confirmation_digest(kind, subject, context)`、`valid_confirmation(...)` | 绑定验收、记忆冲突/设计选择和补充信息确认 |
| `Redactor.sanitize(..., surface=...)` | 日志、证据、UI、模型外发共用过滤器 |
| `Redactor.minimize_for_model(..., fields=...)` | 先显式选择所需字段，再脱敏和截断 |

`Provenance(Source.OWNER, ..., authenticated=True)` 只能由服务端根据有效拥有者会话构建。这个布尔字段不是登录机制。不能从模型工具参数、仓库文件、工具输出、记忆或 HTTP 客户端自行提交的身份标记加载授权、审批或代码信任。仓库中写着“用户已批准”仍是 `Source.REPOSITORY` 数据；Git 提交作者字符串也不能证明拥有者身份。

`OwnerAuthorization` 必须有效且同时匹配 task、project、repository；发布能力单独由 `publish_draft` 限定。控制服务重新加载当前授权/策略版本，不能使用旧 checkpoint 中的授权副本直接恢复执行。

## 工具参数

未知工具、额外字段、类型转换、将 bool 当作 int、空必填字符串和超限参数均拒绝。

| 工具 | 参数与默认限制 |
| --- | --- |
| `read_file` | path；max_bytes=65536，上限 1048576 |
| `search` | query；paths=["."]；max_results=100，上限 1000；查询为字面文本 |
| `write_file` | path、content；内容字符数上限 1048576 |
| `edit_file` | path、old、new；expected_matches=1，必须为 1–1000；old 非空 |
| `diff` | paths=["."]；由受控实现产生差异 |
| `run_command` | argv 字符串数组；cwd="."；timeout_seconds=120，上限 600；max_output_bytes=65536，上限 1048576 |
| `publish_draft` | title、body；branch 默认 decagent/<task-id>，只允许当前任务的分支 |

路径必须相对当前任务工作区。绝对路径、父目录、UNC、驱动器路径、Windows 设备名、备用数据流、越界符号链接和特殊文件拒绝；解析后的路径也重新检查敏感路径。敏感范围包括 `.git/`、`.env*`、`.ssh/`、云凭据目录、控制运行目录、私钥、证书密钥和 socket 等。路径规范化不进行 URL 解码。

读取、搜索和差异可作为静态分析自动继续；这些工具的执行实现不能导入项目模块、运行构建/安装/Git 钩子或仓库脚本。对 search、diff 的每一个返回文件仍须应用 `safe_workspace_path` 和敏感路径排除，不能因为初始目录 "." 通过就递归读取秘密。归档排除敏感内容也属于 broker 的必要责任。

解析路径是执行前检查；实际文件操作必须同时采用防链接替换的打开策略并重查工作区，避免 TOCTOU。纯 Python 路径检查不声称提供操作系统隔离。

## 代码信任与命令

`TrustKind.EXACT_COMMIT` 只认可精确 Git SHA，适用于外部 PR。SHA 改变后必须重新发起 code_trust 审批，旧认可不能覆盖新增外部提交。静态读取仍可继续。

`TrustKind.OWN_BRANCH` 只适用于明确认可的本人分支；分支必须相同，可信服务确认代码来自拥有者，且范围内没有外部提交。陌生贡献者代码、分支变化和外部提交会使该范围不适用。不能依靠仓库文本或未经验证的作者字段判定本人代码。

命令工具接受固定 Python runner 入口 python、python3、pip、pytest、ruff、uv；uv 仅支持 sync、pip、lock 依赖准备。所有 Git 命令、shell、任意绝对可执行文件路径、内联 Python -c、嵌套 shell/容器管理、Docker 管理接口、force push、主分支推送和 merge 没有工具执行入口。差异与草稿发布分别走受控工具。

固定名称只是能力限制，不是命令语义安全证明。即使是 pytest 或 pip 也会执行项目或依赖代码：必须同时满足当前代码信任、明确动作审批和 fresh broker 边界证明。broker 应使用固定 runner 二进制，禁止通过仓库 PATH 解析同名可执行文件。

`ExecutionBoundary` 的任务隔离、网络验证、凭据隔离和资源限制四项必须来自受信任 broker，且全部为 true；缺少任一项即硬拒绝命令。公网访问通过 broker 的受限代理执行，实际 DNS/IP/重定向检查、私网/宿主/控制平面阻断、进程限额及超时终止不由此包实现。

## 精确审批与确认

动作摘要包含工具、规范化参数、task/project/repository、base SHA、当前代码 SHA 与工作区树、物理工作区目标、完整授权/代码信任记录及版本、策略版本、默认分支和执行边界证明。参数顺序不影响摘要，省略默认值和显式默认值相同；参数、代码、授权、策略或工作区变化会使原批准失效。

审批类别为 action、code_trust、acceptance、memory_conflict、clarification。action 与 code_trust 使用 approve/reject；action 可 edit。后面三类使用 confirm/reject，确认内容必须来自有效拥有者会话，且摘要绑定确认对象和相关版本。

edit 消耗旧提议，随后严格校验并重新治理修改后的动作；不会批准旧动作，也不会自动批准新动作。安全修改会返回新的 review 摘要；越界修改直接 deny。reject 阻止该精确动作。重复相同 response_id/内容返回既有结果；同一个 response_id 的冲突内容和不同 id 的第二次回复拒绝。批准只能为同一个 execution_id 领取一次。

代码认可、动作许可和验收确认分别验证，不能将验收确认拿来执行命令，也不能由记忆条目伪造设计选择确认。硬拒绝先于所有模型建议和审批，approve 或 Jev allow 都不能绕过它。

当前是 conservative 版本：安全静态读取自动允许，其他动作没有精确拥有者批准则 review；`semantic_advice="allow"` 不授予非读取自动执行。校准后的 Jev 自动路径尚需单独实现可信的 capability/grant，绑定动作摘要、实际模型、问题/策略版本与校准数据集；不能伪造一个拥有者 Approval 来代替它。

## 控制服务事务接入

顺序为预算预留 → 严格参数与硬规则 → 代码信任 → 必要语义判断 → 必要人工 → 执行前重查。人工等待期间任务必须停止其他工具和仓库进程。

例如可信服务已经加载上下文后，可以这样评估一个纯读取：

```python
from decagent.policy import Action, Outcome, govern

decision = govern(Action("read_file", {"path": "src/parser.py"}), trusted_context)
if decision.outcome == Outcome.ALLOW:
    # 下一步仍由 broker 对当前快照和路径重查，再读取。
    permitted_action = decision.action
```

审批回复的生产流程必须：

1. 验证拥有者认证、CSRF/Origin（浏览器）和任务访问范围。
2. 在 PostgreSQL 中锁定审批行及任务状态；检查 expected_digest 和仍待处理状态。
3. 调用 `reply_to_approval`，原子保存新审批、脱敏审计事件与任务恢复/新审批状态。
4. edit 时根据返回 decision 重新创建提议，不能把修改参数直接交给执行器。
5. 执行前加载最新上下文与审批，重新 `govern`；如果允许，在同一事务中 `consume_approval`、写执行凭据/outbox，并保证任务 lease generation 有效。
6. broker 按稳定 execution_id 去重；崩溃恢复查询执行记录/外部状态，不能从批准回复再次启动命令。

code_trust 应在同一事务内先 `issue_code_trust`，再消费相应 approval 并保存信任版本。确认引用必须指向数据库中经过 `valid_confirmation` 校验的记录。

本包不保证数据库持久性、跨 worker 串行或外部 exactly-once。需要真实 PostgreSQL 并发/重启回归证明这些约束，不能用进程内 dict 或测试拥有者身份代替生产认证。

不可变参数使用 MappingProxyType；序列化到持久化 DTO 时调用 `decagent.policy.canonical.primitive`，不要用会 deepcopy mappingproxy 的 `dataclasses.asdict`。原始动作必须在受控数据库中保存以保持精确绑定；审计、UI 和模型只接收所需字段的脱敏副本。

## 敏感输出与最小化

每个输出 surface（log、evidence、ui、model）使用同一个 Redactor，控制服务将已配置的真实密钥作为 known_secrets 注入，不能把密钥送入容器。匹配项包括精确已知值、GitHub/OpenAI/AWS/Slack 模式、JWT、Bearer/Basic、带口令 URL、私钥 PEM 和密码/密钥/token 赋值；带空格的引号值整体替换，敏感字段名的值直接替换。先脱敏后截断，嵌套深度和集合数量都有上限。日志片段必须在脱敏前组装或使用保持边界状态的受控缓冲，不能直接逐个外发原始片段；此过滤器不保存跨调用的流式状态。

外部模型请求通过 `minimize_for_model` 显式列出必要字段；不接受任意数据库/历史字段，不携带秘密路径的代码片段。片段应来自已经治理过的当前任务读取，不能把其他任务内容伪装为一个安全 path。

未知或无法识别的秘密不能由模式过滤证明安全。可疑内容需要阻止外发并交给拥有者处理；原始敏感输出不落盘，日志、证据和 SSE/UI 都从脱敏结果产生。接口错误详情也需要同样过滤。
