# 使用 mcp-cli 调用模拟工单服务

本指南用于独立客户端兼容性验收。项目业务服务主协议是 `2026-07-28`，本机 `mcp-cli 0.3.0` 按 `2025-11-25` 建立兼容连接；主协议应由 Python SDK `ClientSession.discover()` 验证。所有工单均为本地模拟数据。

## 前置条件

先启动 PostgreSQL、执行数据库迁移与模拟员工账号初始化，再启动两个本机进程：

```powershell
python -m ops.local.start migrate
python -m ops.local.start seed-tickets
python -m ops.local.start plugins install-tickets
python -m ops.local.start business accounts seed
python -m ops.local.start business-server
# 另一个终端
python -m ops.local.start serve --port 8000
```

业务 MCP 默认 `127.0.0.1:8001/mcp`，修复执行 broker 默认使用宿主机端口 `8002`。检查 `http://127.0.0.1:8001/health` 的 `ready` 为 `true`。员工通过 v2 网页登录后签发独立 MCP 凭据；签发 API 返回受保护的 `credential_path`。不要把令牌写进配置 JSON 或聊天消息。

## 隔离配置与调用

仓库自带 [`ops/mcp/mcp_servers.example.json`](../../ops/mcp/mcp_servers.example.json)，只引用环境变量。PowerShell 中将刚签发凭据文件的**实际路径**替换到下列命令：

```powershell
$env:DECAGENT_EMPLOYEE_MCP_TOKEN = (Get-Content -Raw -LiteralPath '<credential_path>').Trim()
$env:MCP_NO_DAEMON = '1'
$env:MCP_MAX_RETRIES = '0'
mcp-cli -c ops/mcp/mcp_servers.example.json info decagent-tickets
mcp-cli -c ops/mcp/mcp_servers.example.json info decagent-tickets tickets_prepare_create
mcp-cli -c ops/mcp/mcp_servers.example.json call decagent-tickets tickets_directory '{}'
```

目录命令返回真实分类 ID。将其作为 `category_id` 并自选固定 `request_id`，即可准备一个创建操作：

```powershell
mcp-cli -c ops/mcp/mcp_servers.example.json call decagent-tickets tickets_prepare_create '{"request_id":"my-first-ticket","params":{"title":"VPN 无法连接","category_id":"<category_uuid>"}}'
```

输出中的 `operation_id` 是后续提交与恢复的唯一句柄。创建操作通常是 `ready`；需人工确认的操作为 `awaiting_approval`。只有原员工在网页工作台核对参数后才能批准；mcp-cli 不能用 Bearer 自批。批准后使用同一个 ID：

```powershell
mcp-cli -c ops/mcp/mcp_servers.example.json call decagent-tickets business_commit_operation '{"operation_id":"<operation_id>"}'
mcp-cli -c ops/mcp/mcp_servers.example.json call decagent-tickets business_get_operation '{"operation_id":"<operation_id>"}'
```

提交调用超时或响应丢失时，先调用 `business_get_operation`。只有返回 `succeeded` 且带原回执才算完成；`running`/`unknown` 表示仍需核实。不要换 `request_id` 重试同一写入。详细恢复规则见 [业务操作恢复与核实指南](2039_业务操作恢复与核实指南.md)。
