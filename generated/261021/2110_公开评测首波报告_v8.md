# DecAgent v8 四域首波真实评测报告

## 路线结果

| 域 | ReAct + Skill + MCP | 一次规划 + PlanRuntime + MCP | 清理 |

| 角色 | 请求 | 已知用量 | unknown 预留 |

按 manifest v8 的首波上限，Qwen 总计入预算 434,960/5,000,000 Token、26/500 请求、Agent 15/300 请求、模拟器 11/160 请求、Judge 0/40 请求；工具 9/1,600 次；批次运行约 449 秒，未触及任一停止线。unknown 的预留量计入额度，但不冒充实际用量。用户确认的约 ¥13.50 是按 5,000,000 Token 全部套用最高冻结单价 ¥2.7/M 推导出的抵扣前上界，不是预期账单或供应商 invoice；代金券只影响实付，不改变该毛 API 费用口径。

已知 21 次请求按冻结费率计算的 `frozen_rate_upper_bound` 为 **¥0.1583867**；5 次 unknown 保留上界约 **¥0.2797192**，合计保守估算约 **¥0.4381059**。这些是 profile 的 CNY 费率计算和未知请求预留，不是供应商 invoice；当前缺少逐请求 provider bill、代金券抵扣及现金实付证据。账本中 provider-billed 金额为零条证据，不能解读成供应商未收费或本次账单为 ¥0。

5/26 的模型 callback 请求没有可用 Token 用量（观察比例约 19.2%）。其中 3 次 Agent 请求异常为 `TimeoutError`，2 次模拟器请求异常为 `RuntimeError`；这是本批观测，不足以估计服务长期故障概率。未知请求没有提供方 request ID，不能安全重放或核对账单。

## 结论与下一步

这次运行验证了批次额度、逐路线隔离、失败隔离、官方评分和 8/8 清理记录路径；**它没有通过每域至少一个官方评分闭环的门槛**：CSM 与 τ retail 没有官方评分，ITSM 与 τ telecom 只有 0.0 的失败评分。不得补跑同一 v8 的 unknown 路线，也不得进入剩余 20 条 smoke 或全量 206+80。

后续先做不产生模型费用的调查：检查 Qwen 与模拟器 callback 的异常路径和 deadline/子进程日志；复核 CSM `find_user` 的 MCP dispatch/receipt；依据可保存的响应证据检查 ITSM `ModelCallError`。没有响应正文的失败保持证据缺失，不还原或猜造模型输出。修复必须先有离线回归，再单独冻结新候选与资源上限；新批次需要重新授权，不能把 v8 的余量自动当作下一批授权。

完整逐路线账本和身份摘要见 [`public-first-wave-live-20261021-v8-5a21ded.json`](../../evals/benchmarks/evidence/public-first-wave-live-20261021-v8-5a21ded.json)。OpenSpec 主 change 仍为 71/79，未通过项见 [tasks.md](../../openspec/changes/jev-conditional-workflows/tasks.md)。
