关联 9.6.F、10.10.E、11.1；Qwen 计费 profile (10.8.D) 与 ledger/runner 接线 (10.10.B/D) 已完成。复用已有 ControlledRoutes、PlanRuntime、模型/gateway factory、规范 SQLite 账本及 supervisor；不按旧计划再新建一套执行引擎。

| 子项 | 需要确认或补齐 | 可验收结果 |
| --- | --- | --- |
| 已修复故障 | Plan 默认 input schema、τ telecom 30-tool schema、模型最短 deadline、单请求 spawned worker | 使用既有定向回归确认有效，未发生配置漂移则复用 Qwen readiness |

## E2：完成真实派发与四域工程验收

关联 9.6.F、10.10.E、11.1。采用受控模型响应和实际隔离工具环境，不产生真实模型费用。固定 τ runtime readiness 为 80/80 ready；最新定向组为 317 passed、1 skipped（177.34s），全量确定性为 1,969 passed、4 skipped，全量 PostgreSQL 集成为 630 passed、24 skipped（1,298.99s）；全仓 Ruff 与 OpenSpec strict 6/6 通过。24 个集成 skip 中 17 个 Docker executor、4 个 Docker repair 仍需专用 Linux 夹具，1 个 benchmark image 未配置，2 个 EnterpriseOps Docker 用例已通过独立 opt-in 复验（2 passed）。首波 dry-run 和镜像核验显示 4 任务/8 路线槽、0 ledger、0 模型/MCP 调用。这些是工程/预检证据，不是公开基准成绩，也不能代替四域真实工具/官方评分/清理、专用 Docker executor/repair 验收与同 SHA CI。

- 逐个实际模型请求执行 reserve → dispatch → settle/unknown；规划、修正、ReAct、总结、语义、模拟器和裁判均独立计数。
- 验证路线及批次额度在同一事务内准入/预留；unknown 保留；跨角色、重启、profile 漂移和错误路径不能绕过规范账本。
- 模型单请求子进程已有实现；补齐任意同步 callback、τ 回调及工具阻塞的强制取消验收。执行 worker 不能持有绕过监督者的发送通道。
- 覆盖“派发标记后挂起 → 接管尝试 → 旧进程恢复”；接管必须等待旧监督进程/后代结束与锁释放。租约失效不能代替生命周期排他。
- 四域分别串联实际工具、官方评分器与 cleanup，包含 τ telecom Plan。故障注入覆盖 unknown 后零新派发、评分异常、清理异常、阻塞和取消。
- 业务终态、评分状态、清理状态和证据分别保存。清理成功不代表未知业务副作用已回滚。
- 将四域验收结果和必需测试资格纳入 live 放行检查；CI 显示绿色但必要边界仍 skip，不能据此放行。

需要验证的现有测试位置包括 public execution/trials/supervisor/model callback、τ process、route execution、EnterpriseOps verifier，以及 test_executor_docker.py、test_repair_docker.py。后两组此前有 21 项因专用夹具未运行，使用独立测试数据库/容器补齐；不操作现有业务库。

结束条件：四域受控闭环和故障矩阵可复现，Ruff、Python 3.11/3.13、适用 PostgreSQL、核心浏览器、wheel/MCP、镜像/Compose 检查有明确结果；失败与环境 skip 分列，必要 skip 未消除时继续阻止相关放行。

## E3：建立新的首波实验

关联 9.6.E/G、10.3。旧首波 8 条路线均为终态，不能在原账本重发。新版本实验必须新建可追溯 cohort，并保留旧失败/unknown/费用预留。

放行顺序：

1. 审阅并提交最终候选；同 SHA 通过本地与远端 CI。当前 160d057 及之后的规划/技能更改均不能借用旧 CI。
2. 固定四域案例、ReAct/Plan 顺序、任务/工具/镜像/τ 版本、模型角色 profile、权限、确认与回复策略。
3. 根据旧账本实际用量和 unknown 预留估算新批次。旧批次的 500 次/500 万 Token/4 小时是旧授权停止线，不自动复制到新 cohort；具体新额度届时给出范围选择。
4. 检查已绑定的 Qwen 费率/profile 与 Jev 累计余额。来源表已核验，但实际账单、缺失用量或尚未实现的 CNY 结算不能猜造；经授权的用量门禁与费用完整性分开。跨币种成本比较必须具备可核验汇率；Jev 仍需单次费用上界及原累计 $1 约束。
5. 执行固定 4 任务/8 路线。Qwen usage unknown 终结该路线，其他合法 pending 路线按批次限制继续；不补跑旧 unknown。
6. 八路线结束或达到停止线后停止新试次并交付报告，先复盘再决定扩大。

旧首波只提供工程估算：4 次 Qwen 请求、18,738 个已知实际 Token、53,508 个 unknown 预留 Token、1 次工具 attempt；不能从这些过早失败的试次推导完整任务平均成本。

## E4：自然 Jev、剩余 smoke 与全量

关联 9.6.D/E、10.3–10.6。

- 已审阅 CSM “从实际返回的已发布知识文章中选择适用文章”模板；保留真实候选、no_match、版本/上下文限制和无写入授权。其余结构化条件继续由代码判断。
- 将同一冻结状态、同一真实候选和同一判断定义分别交给 Jev 与固定 Qwen 语义基线，配对记录质量、延迟、Token 与抵扣前费用。没有适用节点的任务标 N/A。
- 固定 ReAct、一次规划确定性执行、一次规划+Jev 三条路线。确定性路线遇不能处理的语义需求如实记录，不暗加模型。
- 首波闭环后，先补齐 24 个 smoke 任务（还需安排其余 20 个），再评估 EnterpriseOps 206 与 τ official test 80；τ train smoke 另列，不混入 test 成绩。
- 暴露分组、冷启动/热复用、员工显式记忆消融分别预注册；每试次独立状态，不让前例学习流入后例。
- 每轮依据完成试次重新估算费用/时间，冻结下一批额度。数据或模型不支持扩大时保留精确未完成清单。

## 计量、阈值与研究结论

| 指标 | 口径 |
| --- | --- |
| 质量 | 官方任务成功率、错误副作用、未测副作用、自动覆盖与人工介入；每项带准确分母 |
| 时间 | 端到端时间、Agent 机器时间、模拟器/裁判、人工等待分别列出 |
| 用量 | 每次真实模型请求与工具 attempt；重试/格式修正/总结计入，不把问题数当请求数 |
| 费用 | 原币抵扣前 API 成本与来源，voucher/cash 按供应商原始粒度；无可核验换算不统一币种 |
| 完整性 | 已知 Token/未知费用与用量未知分开；未完成配对、评分失败和清理失败全部保留 |
| 统计 | 任务级配对及区间；区间不支持时不给 Jev 提速/降本结论 |

当前每类 40 个开发样例不满足每族至少 100 个自动样本的资格条件。95% 自动正确率目标不变；不通过打开 holdout 或降低目标来发布阈值。

10.5 中真实员工研究继续单列，模拟用户、标签 oracle 和单人合成工作台结果不能替代。10.6 报告必须区分收益成立、未成立和证据不足。
