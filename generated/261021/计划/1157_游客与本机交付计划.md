# DecAgent 游客与本机交付计划

优先级与全局限制见[规划索引](1157_后续规划索引.md)。公开评测受外部条件阻塞时，可以推进以下独立工作；部署与评测仍分别验收。

## G0：保留已完成基础并校正运行版本

游客 1.1–1.6、2.1–2.4 已完成：workspace 身份/数据/记忆隔离、会话、角色切换、7 天 inactivity、停用与安全清理。源码迁移 020–025 的隔离测试已通过，本机正在运行的 v0.1.4 镜像代码仍为 schema 17，不在本轮直接升级。

先更正 2.6 中“入口隐藏证明默认关闭”的证据描述：当前 /api/v3/guest/status 是 HTTP 404。源码默认关闭有配置与测试依据，运行服务尚不包含新接口。后续用对应候选的独立实例做新功能验收。

## G1：游客资源准入

关联 3.1–3.5，先做持久额度/队列，再开放真实模型体验。参考项目内 Supabase PostgreSQL 与 OpenAI 安全编码技能。

| 边界 | 既定要求 | 关键验收 |
| --- | --- | --- |
| 日账本 | 北京时间全站每日 $5 / 500 万 Token；单游客每日 30 任务 / 50 万 Token | 并发不超限；正确分日，旧 unknown 不因跨日释放；重启不能重置占用，清 Cookie 后全站额度与创建限流仍生效 |
| 模型准入 | 任务/游客/全站原子预留，实际结算；unknown 保留 | 无可靠价格上界拒绝真实游客派发；代金券不折算成零费率 |
| 并行和队列 | 单游客 1、全站 2、等待 20 | 排满拒绝不占任务次数；合法取消、租约恢复、公平领取和不双执行 |
| 限流 | 创建、提交、回复；只信显式受信代理 | 429/Retry-After 与 UI 提示一致；伪造转发头不能换身份或绕限 |

迁移使用实施时的下一可用序号；不假定运行库已升级。业务与公开评测账本分别验证，不能借试用日预算扩大 Jev 评测原累计 $1 授权。

当前 Qwen 的[千问平台适用费率已核验](../模型计费/1441_千问平台费率核验.md)。实现游客准入前还需绑定 CNY 计费/缓存口径并冻结可核验的 CNY/USD 换算，才能共同约束全站 $5；不能把数值 0.8/2.7 当作美元单价，或把已有 OpenRouter DeepSeek 备用路线套上千问平台价格。

## G2：真实建议与浏览器验收

关联 2.5、2.6、6.1。

- 创建一次性测试数据库和候选对应的独立 API/Worker/MCP；游客开关只在该命名测试实例显式开启，当前工作实例仍关闭或保留旧版本。
- 复用现有工作台，不重新开发游客 UI。Node 已覆盖六类交互，但还需实际浏览器验证 Choice/Noul/Score、无匹配、补充、拒绝与独立写入确认。
- 真实 Jev 建议必须来自受控请求与持久记录，关联请求/模板/节点；用户选择不能授予业务写权限。缺合格阈值继续人工选择。
- 真实 Jev 接入测试先核对原累计账本和单次费用上界，再提出最小明确范围；不把脚本响应当成真实模型验收。
- 两浏览器空间、角色切换、刷新/退出/7 天失效、稳定记忆槽、审批和 unknown 恢复均走服务端隔离验证。
- 按游客指南完整走通开始、恢复、切换和清空后，才勾选 2.6；保留截图、浏览器日志和测试实例清理结果。

webapp-testing 作为网页测试参考。现有夹具与生产监督逻辑继续负责进程树、数据库和 MCP 回收；通用辅助脚本不代替这些验收。

## D1：SOP 本机部署与恢复

关联 4.1–4.4。应用仓库、部署配置和 CI/CD 分开交付。

- 新 SOP Compose 包含 API、business Worker、business MCP 和 PostgreSQL，默认只绑定 loopback；repair/executor 保留兼容边界。
- 健康验收包括 Worker/MCP 和可清理空间中的零付费合成业务链，API /health 成功不能掩盖业务故障。
- 保存旧 digest/config/schema 与备份；候选升级后做业务探针，失败时先检查旧应用对当前 schema 的兼容性。兼容则回滚应用，不兼容则停止并保留人工恢复材料，不自动覆盖数据库。
- 在隔离副本演练 schema 17 到当前迁移序列，再安排真实本机升级；不把新代码直接指向旧库试错。
- 核验 Windows 登录、Docker Desktop 重启和服务恢复。用户接受短时中断，不宣称 7×24 或独立 Linux 验收。

参考 docker-compose-patterns 和已有 ci-cd-pipeline-builder；镜像 digest、网络隔离、备份与 schema 兼容要求以项目规格为准。

## D2：公共 CI 与 GHCR

关联 5.1、5.5 和主任务 11.1。优化先依据每个 job 的实际关键路径和缓存命中率，不通过删测试或忽略 skip 来缩短时间。

- 独立 lint/Node、Python 矩阵、数据库、浏览器、wheel/MCP、镜像/Compose 工作按依赖分层并行。
- uv 缓存绑定锁文件/平台/Python；镜像缓存绑定 Dockerfile 和依赖摘要；构建/安装产物验证使用相同候选来源。
- 数据库测试使用隔离库与有界并发；确认真实 Docker/SQL 夹具就绪，避免 CI 绿色仍遗漏必需容器边界。
- 优化前后分别报告 job 时间、总墙钟、命中率及失败/skip；Python 3.11/3.13 等已承诺检查保持，若要改变矩阵覆盖需另行修订规格。
- 普通 CI 不调用付费模型。公共 release 继续只负责受信 CI 和 GHCR 发布。

## D3：私有 CD 到本机

关联 5.2–5.4。完成本机 SOP 健康、备份与回滚后，再创建和配置私有 DecAgent-deploy。

- 先实现并离线验证发布来源检查器：固定仓库、tag/SHA、main 祖先关系、成功 CI/run attempt、镜像来源和 digest；拒绝任意路径/脚本/镜像输入。
- 本机 Runner 只注册私有部署仓库；公共仓库无自托管调度入口。触发凭证按最小权限设置，到配置时再请求必要的人机操作，不把密钥写入文档。
- 私有受审脚本串行拉取已验证 digest、备份、升级、业务探针和兼容回滚；不执行 dispatch 指定的公共代码。
- 全链路演练记录 commit、CI/release run、digest、健康结果、失败分类与恢复结果。

先使用项目安全技能审视匿名用户、模型凭证、MCP 与 Runner 的具体信任边界。最终仍需实际发布和故障演练，安装技能不构成安全验收。
