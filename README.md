# DecAgent

DecAgent 是基于 LangGraph 的业务 Agent，通过 **MCP + Skill** 接入业务能力。
主模型处理复杂规划，Jev 提供有限选项的类型化判断，
程序管理员工权限、人工介入、预算、持久状态与可核实回执。

项目关注的是：什么时候可以继续，什么时候需要补充事实或具体确认，
以及发生超时、重启和并发时如何判断业务是否真的完成。
当前内置本地模拟服务工单，包含创建、分配、处理、解决、关闭和重开。
员工、处理人和主管使用不同权限；未接入御龙后端或真实公司业务 API。
仓库修复保留在独立入口。

## 当前实现

| 边界 | 实现 |
| --- | --- |
| 业务协议 | 官方 MCP SDK 2.3.0；主协议 2026-07-28，兼容 2025-11-25 |
| 业务能力 | service-tickets 2.0.0；12 个领域命令，14 个网络工具 |
| 员工身份 | 固定任务员工；12 小时浏览器会话、1 小时独立 MCP token |
| 具体确认 | 原员工网页批准；15 分钟有效期；编辑产生新操作 |
| 写入一致性 | 不可变 prepare；commit 重查权限；工单/历史/回执同事务 |
| 异常恢复 | 先查询原 operation_id；核实回执后决定原 ID 是否可恢复 |
| Agent 约束 | 隐藏 grant 绑定任务、动作、预算、契约、员工和租约代次 |
| 持久执行 | 默认 business-2；开关选择 business-3，兼容 worker 按原版本恢复；源码 schema 17，当前用户业务库未迁移 |

LLM 只能提出注册命令与业务参数。Jev 的分支、命题与评分尺来自程序和版本化契约，
动态候选来自实际 MCP 查询；模型不能改写权限或自我批准。
业务 CLI 执行入口已移除，本地管理 CLI 继续负责初始化、注册和运维。

## 验证与限制

[本机启动烟测](generated/261014/1646_MCP本机启动烟测.json)已经验证员工任务通过 MCP
产生一个成功操作和一张回执，模型调用为 0，历史匿名工单与 owner 保留。
[固定多角色验收](generated/261014/1649_MCP多角色业务验收.json)为 11/11，
禁止的业务副作用为 0；包含并发重复提交、模拟响应丢失与真实服务重启。
脚本验收中的机器耗时与人工等待分别记录，不代表真实模型性能或企业提效。

新 MCP 契约尚无验收通过的 Jev 校准配置。旧 business-2 hybrid 在缺少兼容校准时转交主模型；新 business-3 的关键判断进入原员工语义待办，不以主模型兜底低分判断。
旧 CLI/Jev 对照绑定旧源码与数据集，不能用于证明当前 MCP 版本加速。
独立 Linux 主机部署仍待验收，本机 Docker Desktop 测试不替代该项。
